# Changelog

Версии шаблона `agentic-project-template`. Новые — сверху. Релиз — git-тег `vX.Y.Z` (semver, правила
нумерации — `setup/DESIGN.md` §5.4); номер версии совпадает с `setup/VERSION`.

Формат раздела:

```
## [X.Y.Z] — YYYY-MM-DD

### Добавлено
### Изменено
### Исправлено
### Миграции
```

- Пустые подразделы «Добавлено», «Изменено», «Исправлено» опускаются.
- «Миграции» обязательны всегда: скрипты `setup/migrations/<x.y.z>_*.py`, что они меняют в проекте
  (особенно в Знаниях) и что проверить после них. Если миграций нет — «Нет».
- Пишите так, чтобы Агент при обновлении мог объяснить человеку, что меняется и чем это грозит: ломающие
  изменения команд `tb`, протокола в `AGENTS.md` и структуры проекта отмечайте явно.
- Невыпущенная версия помечается «не выпущено» вместо даты.

## [0.5.0] — не выпущено

Знания коммитятся сразу и с сессией-автором; новый тип Знаний — напоминания; в конце сессии Агент
предлагает взять в работу близкие напоминания, планы и задачи.

### Добавлено

- `tb kb commit <пути> -m "…" [--amend]` — коммит Знаний сразу после правки. Берёт только указанные пути
  внутри `Knowledge/` (`git commit --only`): проиндексированное параллельными сессиями в коммит не
  попадает и остаётся в индексе. Префикс `knowledge:` и трейлер `Agent-Session: <агент>:<id> (<заголовок>)`
  (id: Claude Code — из `CLAUDE_CODE_SESSION_ID`, другие агенты — `AGENTIC_SESSION`; заголовок задаёт агент
  командой `tb kb session title "…"`, без него — только id). `--amend` правит последний коммит этой
  сессии с этими путями: amend, если он HEAD, иначе коммит `fixup!`; запушенное не переписывается.
  Без включённых git-хуков (`tb setup`) команда откажет.
- `tb kb squash [--dry-run]` — склеивает `fixup!` с их коммитами (autosquash без интерактива), только при
  чистом рабочем дереве и незапушенных коммитах.
- Тип Знаний `reminder` (`Knowledge/Reminders/`, шаблон `_templates/reminder.md`): что рассмотреть
  в ближайшее время — ссылки на заметки, планы, задачи, необязательный `due`. Поиск находит напоминание
  и по словам заметок, на которые оно ссылается; хук `kb-suggest` показывает пересекающиеся с запросом
  напоминания отдельным списком; `tb kb stale` — в день `due`, без `due` — через 14 дней; `tb kb lint`
  проверяет `due` и предупреждает о напоминании без ссылок на заметки.
- `tb kb nearby [<заметки>] [--query] [--resource]` — напоминания, открытые планы и задачи рядом
  с контекстом: общий ресурс или модуль, ссылки, теги, слова; у каждого — причина.
- Хуки `kb-track` (after-tool, только инструменты правки) и `kb-uncommitted` (stop): первый запоминает
  файлы Знаний, которые правит сессия (`Runtime/sessions/`), второй один раз просит Агента закоммитить
  оставленные незакоммиченными. В `hooks.toml` — поле `tools` (категория `edit`), в `adapter.toml` —
  `[hooks] matchers`. У Codex соответствие для `edit` пока не задано: `kb-track` пропускается
  с предупреждением.

### Изменено

- **Протокол коммитов (`AGENTS.md`, skills):** Знания Агент коммитит сразу после правки и сообщает
  человеку, без просьбы; остальное — по-прежнему только по просьбе. Skill `kb-commit` переписан под
  `tb kb commit`; `wrap-up`, `kb-review`, `plan-review` коммитят применённое сами.
- `wrap-up`: шаг «Что ещё рядом» — `tb kb nearby` по задаче сессии и предложение взять близкое в работу
  (в этой сессии или в новой с брифом); отложенное «к сроку» — напоминанием.
- `kb-lookup` и `librarian`: строка «Напоминания» в ответе. `plan-review` учитывает напоминания о плане.
- Claude Code: без подтверждения разрешены `tb kb nearby`, `tb kb commit` и `tb kb session`.
- `tb kb stale`: порог для задач `active`/`blocked` — 14 дней вместо 30.

### Миграции

- `0.5.0_knowledge-commit-hooks.py` — дописывает хуки `kb-track` и `kb-uncommitted` в проектный
  `.agents/hooks/hooks.toml`, если их там нет; проект без `hooks.toml` не трогает. После update —
  `Toolbox/tb agents link`, Codex попросит одобрить новый хук в `/hooks`.
- Папка `Knowledge/Reminders/` и шаблон `_templates/reminder.md` приходят как новые файлы (`add`), миграции
  Знаний не нужны.

## [0.4.0] — 2026-10-22

Модуль `adopt` — перенос большого проекта по итогам пилота: этапы, реестры, аудит, очистка по манифесту.

### Добавлено

- Необязательный модуль `adopt` (`init --with adopt` или skill `agentic-update`, «добавить модуль»; после
  очистки старого его снимают тем же skill, данные переноса в задаче остаются):
  - skill `adopt` — оркестрация переноса по этапам с критериями «Готово, если»: подготовка, инвентаризация,
    ресурсы, правила и пилот, перенос пачками, вопросы, консолидация, финальный аудит (блоки A–F, GO/NO-GO,
    манифест удаления), очистка. Рядом — базовые правила переноса (`rules.md`), поручения рабочему,
    аудитору и проверяющему финального аудита (`prompts/`), заготовки артефактов задачи (`templates/`);
  - субагенты `adopt-worker` (переносит пачку) и `adopt-auditor` (пишет только колонку «Аудит» или свой
    файл раздела);
  - `tb adopt`: `start` (задача из заготовок с `adopt.toml`), `inventory` (репозитории с вложенными,
    локальная работа против `ls-remote`, устаревшие `origin/*`, stash, грязное, ценное неотслеживаемое;
    `--compare` со снимком), `sources` (кандидаты в источники знаний), `manifest`, `slugmap`, `next`,
    `links` (`[[wikilinks]]` → относительные ссылки, ещё не перенесённое — отложенные `"pending"`),
    `check`, `gate` (шлюз перед общим коммитом: покрытие, аудит, принятые передачи), `status`, `refs`
    (старые пути в окружении), `digest` (дайджесты транскриптов с маскировкой секретов), `archive`
    (tar.gz вне проекта, права 600, сверка sha256).
- `setup/INIT.md`: модуль `adopt` в интервью; малый и большой adopt разведены, большой — init
  `--with adopt` и skill.

### Изменено

- `Toolbox/agentic/cli.py` знает команду `adopt`: без модуля её просто нет.
- Профили `software` и `generic`: `adopt` в списке необязательных модулей.

### Миграции

Нет. Модуль новый и необязательный; существующие проекты не меняются. Перенести большой проект —
skill `agentic-update`, «добавить модуль adopt», затем новая сессия агента и skill `adopt`.
`Toolbox/README.md` — seeded: строка о `tb adopt` в существующие проекты не придёт.

## [0.3.0] — 2026-10-22

Доработки по итогам пилота adopt крупного проекта: перенос знаний пачками и параллельными сессиями,
ресурсы с вложенными репозиториями, разрешения проекта, ревью больших баз Знаний.

### Добавлено

- `tb kb verify <путь|slug>…` (`--date`, `--dry-run`) ставит `verified` на сегодня и линтует заметки, так
  что после ревью frontmatter не правят руками. Меняется только значение `verified`. Правка проверяется
  разбором YAML: если безопасно поменять нельзя, файл остаётся как был, а tb просит поправить вручную.
- Отложенная ссылка `[текст](путь.md "pending")` — ссылка на заметку, которой ещё нет. `tb kb lint` выдаёт
  предупреждение и коммит не блокирует. Когда цель появилась, lint подсказывает снять title. `tb kb stale`
  показывает такие заметки, `tb kb related` помечает ссылки `[pending]`.
- `resources` во frontmatter принимает подпуть внутри ресурса (`<ресурс>/<подпуть>`, `<ресурс>/<подпуть>@<ветка>`),
  например модуль ресурса-монорепозитория или вложенный репозиторий. `tb kb lint` предупреждает, если подпути
  нет в склонированном ресурсе. `tb kb search --resource X` находит и `X/…`.
- `tb kb lint` проверяет поле `entity` каталога: если файла нет — ошибка. Если у ресурса нет `entity`, а
  карточка в `Entities/` названа его именем (или это единственная карточка, где он указан целиком), lint
  подсказывает готовую команду `tb resources set`.
- `tb resources set <name> <поле>=<значение>…` правит запись каталога с сохранением комментариев;
  пустое значение удаляет поле. `tb resources add --entity <путь>`.
- Поле каталога `agent_settings_reviewed`: `tb resources status` и `tb agents doctor` больше не
  предупреждают о разобранных настройках агентов внутри ресурса. О новых путях предупреждают и
  подсказывают команду.
- `.agents/permissions.toml` (seeded) задаёт разрешения проекта для всех агентов: `[[command]]` с префиксом
  команды и `decision = deny|ask|allow`, а `[claude]` — для правил, которые понимает только Claude Code.
  `tb agents link` переносит их в `permissions` файла `.claude/settings.json` (вместе с разрешениями `tb`
  от шаблона) и в `.codex/rules/project.rules` (`prefix_rule`; Codex читает их только в доверенном проекте,
  rules у Codex пока экспериментальные). `[claude]` для Codex пропускается с предупреждением. Токены
  `prefix` не должны содержать пробелы, кавычки и `*`: такие правила пропускаются с предупреждением,
  потому что Claude Code и Codex поняли бы их по-разному. Правила с шаблоном в середине (`git -C * push`,
  `curl * | sh`) пишите в `[claude]`: `prefix_rule` у Codex сравнивает argv только с начала. Если файл не
  разбирается, `tb agents link` оставляет прежние файлы разрешений и завершается с ошибкой, `doctor`
  показывает ✗: битый файл не снимает запреты молча.
- `tb agents link` и `doctor` выводят предупреждения об общих источниках `.agents/` (permissions, hooks,
  mcp, субагенты) один раз, а не для каждого агента. Ожидаемые пропуски (например, `[claude]` у Codex)
  показываются как информация, а не как постоянное предупреждение.
- `kb-auditor` умеет отчитываться в файл: получив путь `Runtime/…`, он пишет полный отчёт туда, а отвечает
  сводкой до 10 строк. При большом охвате (больше ~30 заметок) `kb-review` и `plan-review` включают этот
  режим, чтобы отчёты не переполняли контекст основного Агента.
- `setup/INIT.md`: ресурсы и adopt большого проекта можно отложить на отдельный этап с задачей. Новый
  сценарий «новый проект на месте старого»: что переносить вручную при переименовании старой папки
  (история и память Claude Code, `includeIf` в `~/.gitconfig`, сессии Codex, IDE).

### Изменено

- **`AGENTS.md` (блок шаблона).** Блок сокращён: убрана строка «Skills шаблона» (она повторяла описания
  skills), сжат список команд. Добавлен запрет обходить или отключать pre-commit (`--no-verify`, `commit-tree`): хук
  ловит секреты. Правило «коммиты — только после подтверждения» слито с «коммить только по просьбе
  человека», смысл не изменился.
- **Бюджет `AGENTS.md`.** `tb kb lint` считает только проектную часть вне блока `agentic:begin/end`
  (≤ ~800 токенов), а размер блока шаблона (≤ ~900) проверяют тесты шаблона. Файл без маркеров, как и раньше,
  ограничен ~1500 токенами целиком.
- `tb kb lint --staged` (pre-commit): если цель ссылки есть на диске, но ещё не в индексе, это теперь
  предупреждение, а не ошибка `broken link`. Параллельные сессии в одном дереве могут коммитить свои
  заметки раздельно. Цель, которую git игнорирует (например, `Runtime/…`), по-прежнему ошибка: в репозиторий
  она не попадёт никогда. Так же проверяется `entity` каталога.
- `kb-review`, `plan-review`, `kb-auditor`, `librarian`: отрицательное утверждение («нет в коде») доказывается
  только поиском без учёта ignore-файлов (`rg --no-ignore`, `git -C <репозиторий> grep`), включая вложенные
  репозитории. Пачки собираются по `<ресурс>/<подпуть>`, `verified` ставится через `tb kb verify`.
- `kb-commit`: хук не обходится. Предупреждение `not staged yet` от `lint --staged` разбирается при проверке
  индекса: заметку коммитят вместе со ссылкой или помечают ссылку как отложенную.
- `Resources/README`, раздел «Поиск». Ripgrep не видит вложенные репозитории ресурса, перечисленные в его
  `.gitignore`. Вернуть их можно точечным правилом `!/Resources/<ресурс>/<путь>/` в проектной части
  корневого `.ignore` или искать через `rg --no-ignore` и `git -C <репозиторий> grep`. Поиск, учитывающий
  только `.gitignore` (например, `grep` в оболочке Claude Code), не видит `Resources/` от корня. Пустой
  результат такого поиска — не доказательство отсутствия.
- README Знаний: в Знания не пишут реальные данные клиентов и пользователей (выгрузки, персональные данные).

### Миграции

Нет. После обновления:

- выполните `Toolbox/tb agents link` на каждой машине (на свежем клоне без `.agents/local.toml` — сначала
  `Toolbox/tb setup --agents <…>`);
- перенесите разрешения проекта (например, deny/ask из `.claude/settings.local.json`) в `.agents/permissions.toml`;
- отметьте разобранные настройки агентов в ресурсах: `Toolbox/tb resources set <name> agent_settings_reviewed=…`;
- проверьте `Toolbox/tb kb lint`: новые проверки `entity` и подпутей `resources` могут дать ошибки и подсказки;
- если проектную часть `AGENTS.md` ужимали под старый общий бюджет, её можно расширить до ~800 токенов.

Файлы `Resources/resources.toml` и `Toolbox/README.md` — seeded: новые комментарии и строки о командах
в существующие проекты не придут (update покажет их как `seeded-changed`).

## [0.2.0] — 2026-10-13

### Добавлено

- Skill `plan-review` — ревью бэклога Plans. Проверяет, что сделано или неактуально (с доказательством),
  находит дубликаты и пересечения с активными задачами и проверяет критерии готовности к работе.
  Человек получает предложенный порядок работ.
- `tb ide setup`, вызывается и из `tb setup`: IDE не индексируют `Resources/` и `Runtime/`. Для JetBrains
  команда добавляет `excludeFolder` в модуль `.idea/*.iml` (а если `.idea/` нет, пишет минимальный проект),
  для VS Code — `search.exclude` и `files.watcherExclude` в `.vscode/settings.json`. Остальные настройки
  пользователя сохраняются, папки остаются видимыми.
- Субагент `kb-auditor` (только чтение) проверяет пачку заметок по Ресурсам и истории git и возвращает
  по каждой вердикт с доказательством. Правила он берёт из `SKILL.md` вызвавшего skill.

### Изменено

- Skill `kb-review` переписан. Появились цель и критерии приёмки, границы (охват, только чтение при
  сверке, подтверждение человека) и вердикты `keep`/`fix`/`shrink`/`merge`/`delete`/`ask`. Каждый вердикт
  требует проверяемого доказательства, для каждого типа заметок заданы критерии. Проверка идёт пачками
  по ресурсу через параллельных субагентов `kb-auditor`, отчёт — в фиксированном формате. Plans перешли
  в `plan-review`.
- `AGENTS.md` (блок шаблона): в протоколе и списке skills появился `plan-review`.
- **Знания хранят только живое.** Отжившая заметка удаляется, история остаётся в git. Упразднены статусы
  `superseded` и поле `superseded_by` у decision, `dropped` у plan. У gotcha и example поля `status` больше
  нет. Заменённое решение удаляется, а причина замены записывается в новое; отвергнутый план удаляется,
  важная причина отказа оформляется решением. `deprecated` у entity означает «выводится, но ещё есть».
- `tb kb lint` для упразднённых статусов, `superseded_by` и `status` у gotcha/example выдаёт
  предупреждения, а не ошибки, поэтому коммиты Знаний они не блокируют. `tb kb stale` показывает
  заметки с упразднёнными статусами как кандидатов на удаление. В выводе `tb kb` у заметок без
  статуса — только тип.
- README Знаний и типов, skills `wrap-up`, `kb-lookup`, `kb-review`, субагент `librarian` и шаблоны
  заметок `gotcha`, `example` переписаны под новые правила. Шаблоны seeded: update предложит изменения,
  а их часть, касающуюся `status`, применит миграция.

### Миграции

- Для исключений в IDE миграции нет: после обновления выполните `Toolbox/tb setup` или `Toolbox/tb ide setup`
  на каждой машине.
- `0.2.0_drop-status-gotcha-example.py` убирает строку `status: active` из frontmatter заметок
  `Knowledge/Gotchas/`, `Knowledge/Examples/` и шаблонов `Knowledge/_templates/gotcha.md`, `example.md`.
  Заметки с упразднёнными статусами (`resolved`, `outdated`, `superseded`, `dropped`) миграция не трогает.
  После обновления выполните `tb kb lint` или skill `kb-review`: такие заметки нужно удалить с согласия
  человека.

## [0.1.1] — 2026-10-13

### Добавлено

- `tb resources clone <name> --from <путь>`: клон из локальной копии, пока upstream недоступен; `origin`
  выставляется на url каталога. `tb resources add <локальная копия> --clone` делает это сам, если
  upstream не отвечает.

### Исправлено

- Init отказывается работать в клоне шаблона внутри другого Agentic Project (например, ресурс
  `Resources/agentic-project-template`): раньше он заменил бы `.git` ресурса.
- Init ставит в проект только файлы payload, которые git отслеживает или готов отследить. Раньше
  игнорируемые git файлы внутри `payload/` (`.idea/`, `.obsidian/`, `Runtime/`) тоже попадали в проект
  и в `agentic.lock`, а проверка чистоты клона их не видела. Без git (распакованный архив) пропускаются
  те же служебные каталоги.
- Копия `tb` в `payload/modules/core/Toolbox/` без `TB_ROOT` отказывается работать (хук молча выходит
  с 0). Раньше она создавала `Runtime/` с uv и Python внутри payload. На `tb` развёрнутого проекта
  это не влияет.
- Документация: ветка обновления в `setup/UPDATE.md` называется по `setup/VERSION` скачанной копии,
  а не по имени каталога; `setup/DESIGN.md` §5.2 — хэши в lock есть у файлов всех классов.

### Миграции

## [0.1.0] — 2026-10-09

### Добавлено

- Раскладка шаблона: инсталлятор `setup/` и модули `payload/modules/<module>/`; модули `core`,
  `knowledge`, `resources`, `obsidian` и необязательный `devcontainer`; профили `software` и `generic`.
- Инициализация: `init.sh` / `init.cmd` → `setup/init.py` (флаги `--name`, `--language`, `--profile`,
  `--with`, `--without`, `--agents`, `--yes`, `--dry-run`), новый git-репозиторий с коммитом
  `agentic: init from template vX.Y.Z` из явного списка файлов (остатки папки шаблона не коммитятся,
  локальная git-identity клона сохраняется), настройка машины. Init предупреждает о развёртывании
  из состояния разработки. Инструкция Агенту — `setup/INIT.md`, включая обёртывание существующих
  репозиториев (adopt).
- Версии: релиз `X.Y.Z` (тег `vX.Y.Z`), между релизами `setup/VERSION` = `X.Y.Z-dev`; проект из состояния
  разработки получает релиз обновлением.
- `.agents/agentic.lock`: источник, версия и коммит шаблона, параметры проекта, классы владения
  (`managed`, `seeded`, `block`) и хэши установленных файлов. `block`-файлы — `AGENTS.md`, `.gitignore`,
  `.gitattributes`, `.ignore` (маркер — целая строка); шаблоны заметок и `devcontainer.json` — `seeded`.
- Toolbox: `Toolbox/tb` и `Toolbox/tb.cmd` скачивают закреплённый uv (0.12.23, проверка sha256) и Python
  в `Runtime/`; команды `tb version`, `tb kb`, `tb secrets scan`, `tb hook`, `tb agents`, `tb resources`,
  `tb setup`, `tb obsidian setup`, `tb update fetch`, `tb run`. `tb hook` никогда не блокирует агента
  и ничего не скачивает; унаследованный `TB_ROOT` не перенаправляет `tb` проекта.
- Знания: типы Decisions, Entities, Examples, Gotchas, Plans, Tasks с README и шаблонами заметок; поиск
  BM25 со стеммингом Snowball (RU/EN), проверка `tb kb lint` (frontmatter, ссылки, имена файлов, бюджет
  `AGENTS.md`; `--staged` — по содержимому индекса git), `tb kb new --description`, кандидаты
  на перепроверку `tb kb stale`.
- Skills `kb-lookup`, `kb-commit`, `kb-review`, `wrap-up`, `agentic-update`; субагент `librarian`.
- Адаптеры `claude` (Claude Code) и `codex` (Codex): skills, субагенты, хук `kb-suggest`
  на `prompt-submit`, MCP из `.agents/mcp.toml`, отключение встроенной памяти агентов. Claude получает
  генерируемый `CLAUDE.md` с `@AGENTS.md`; хук Codex находит корень проекта сам (без абсолютных путей).
- Ресурсы: `tb resources add <путь к локальной копии>` записывает её `origin` и предупреждает о работе,
  которой нет в upstream; `tb resources status` и `tb agents doctor` перечисляют настройки агентов
  внутри ресурсов, которые из корня проекта не загружаются.
- Git: `pre-commit` (`tb kb lint --staged` для Знаний и поиск секретов: ключи провайдеров, JWT, `Bearer`,
  пароли в URL и присваиваниях), настройки `core.hooksPath`,
  `core.quotePath=false`, на Windows — `core.longpaths=true`.
- Обновление: `tb update fetch`, `setup/update.py` (`plan`, `diff`, `apply`), инструкция `setup/UPDATE.md`,
  миграции `setup/migrations/`. Изменение состава проекта: `--add-module`, `--remove-module`, `--language`,
  `--profile`.
- Языки `ru` и `en`; проверка переводов `setup/i18n_check.py`; unit-тесты `setup/tests/unit_test.py`
  и smoke-тест `setup/tests/smoke_test.py`.
