# Agentic Project concept

Reference for the Agent: read it when you need to understand the project's design in more depth than
`AGENTS.md` covers.

## Overview

Agentic Project is a workspace where the Agent works across all of the project's Resources. A project is
not a single repository but a connected whole: a root git repository with instructions, tools and
Knowledge, plus Resources — separate repositories or folders. The project was deployed from the
`agentic-project-template` template and is updated from it.

Principles:

- `.agents/` is the single source of truth for system files. `.claude/`, `.codex/`, `.mcp.json`
  are generated by `tb agents link` and are not committed to git.
- Level 0 is enough: read `AGENTS.md` and run commands. Native skills, subagents and hooks are an
  enhancement, not a requirement.
- Project memory is `Knowledge/` only, not the agent's built-in memory (`~/.claude`, `~/.codex`).
  Knowledge holds only what cannot be derived from Resources and git history.
- `tb` does the mechanics, the Agent does the meaning: interviews, analysis and writing live in skills.
- Cheap start: at startup, only `AGENTS.md` and skill descriptions; Knowledge on demand.
- Irreversible actions (deleting data, updates, commits) happen only with the human's confirmation.

## Structure

| Path | What it is |
|---|---|
| `AGENTS.md` | Entry point: map, rules, session protocol |
| `.agents/agentic.lock` | Template origin, project parameters, file classes and hashes. Do not edit by hand |
| `.agents/local.toml` | Agents on this machine; not in git |
| `.agents/skills/<name>/SKILL.md` | Procedures |
| `.agents/agents/<name>.md` | Subagents in the canonical format |
| `.agents/hooks/hooks.toml` | Hooks on abstract events; command — `Toolbox/tb hook <name>` |
| `.agents/git-hooks/` | `pre-commit`: `tb kb lint` for Knowledge, secret scan |
| `.agents/adapters/<agent>/` | Agent adapter manifests |
| `.agents/mcp.toml` | MCP servers |
| `Knowledge/` | Knowledge, an Obsidian vault; rules — `Knowledge/README.md` and the folder READMEs |
| `Resources/` | Resources; rules — `Resources/README.md`, catalog — `Resources/resources.toml` |
| `Toolbox/` | `tb` / `tb.cmd`, template tools in `agentic/`, project tools; index — `Toolbox/README.md` |
| `Runtime/` | Temporary files and the environment (`tools/`, `cache/`, `update/` are reserved); not in git |

## File ownership

The class of every file that came from the template is recorded in `.agents/agentic.lock`.

| Class | Owner | How to edit |
|---|---|---|
| `managed` | template | Do not edit. A local edit becomes a conflict on update. Put project-specific content in project files |
| `seeded` | project | Edit freely: the template created the file once and never touches it again |
| `block` | mixed | Edit only outside the `agentic:begin` / `agentic:end` markers; the template updates the block between them |
| not in the lock | project | Edit freely |

Do not edit the generated `.claude/`, `.codex/`, `.mcp.json`: change the source in `.agents/`, then run
`Toolbox/tb agents link`.

## Knowledge

| Type | What it stores |
|---|---|
| Decisions | Architecture decisions (ADR), permanent; outdated ones — `superseded` |
| Entities | Entity cards: purpose, location, relations, invariants, owners |
| Examples | Reusable examples and templates |
| Gotchas | Pitfalls: symptom, cause, workaround, how to check it still applies |
| Plans | Ideas and postponed work |
| Tasks | Current tasks; after `done`, the takeaways are moved to other types and the task is deleted |

Workflow: `tb kb search` → `tb kb show` → check against Resources. Skills: `kb-lookup`, `wrap-up`,
`kb-commit`, `kb-review`.

## Agents

Levels: 0 — `AGENTS.md` and commands; 1 — native skills; 2 — subagents; 3 — hooks. Without native skills:
find the skill in `.agents/skills/` and read its `SKILL.md`. Adapters: `tb agents list`, `tb agents link`,
`tb agents doctor`.

## Git

- Root repository: `AGENTS.md`, `README.md`, `.agents/`, `Knowledge/`, `Toolbox/`,
  `Resources/README.md`, `Resources/resources.toml`. Not in git: `Resources/*`, `Runtime/`, adapter
  outputs, `.agents/local.toml`, `Knowledge/.obsidian/`, `.env*`.
- Resources are committed inside themselves: `git -C Resources/<name> …`.
- Commits — on request, with explicit paths, in the format `<scope>: <summary>`; scopes: `knowledge`,
  `agents`, `toolbox`, `resources`, `agentic`.

## Lifecycle

- **New machine:** `git clone <project-repository>`, then `Toolbox/tb setup --agents <a,b>` (Windows:
  `Toolbox\tb.cmd setup --agents <a,b>`): uv and Python in `Runtime/`, adapters for the listed agents
  (remembered in `.agents/local.toml`), git and Obsidian settings, a list of missing resources
  (`--clone-missing` clones them). The same command restores the
  environment after `Runtime/` has been deleted; to add a new agent — `Toolbox/tb setup --agents <a,b>`.
- **Update:** skill `agentic-update` → `Toolbox/tb update fetch` downloads the latest template release
  into `Runtime/update/<v>/` → follow `Runtime/update/<v>/setup/UPDATE.md` from that copy. Changes go
  on the `agentic/update-<v>` branch; commit and merge only after the human confirms. The source is the
  URL in `agentic.lock`; only the human may change it.
- **Template version:** `Toolbox/tb version`.

## Where to look

| Question | Where |
|---|---|
| Knowledge rules, note format | `Knowledge/README.md`, `Knowledge/<Folder>/README.md`, `Knowledge/_templates/` |
| Resources, what is cloned | `Resources/README.md`, `Toolbox/tb resources status` |
| Tools | `Toolbox/README.md`, `Toolbox/tb --help`, `Toolbox/tb <command> --help` |
| Procedures | `.agents/skills/` |
| Project parameters and version | `Toolbox/tb version`, `.agents/agentic.lock` |
| Agent problems | `Toolbox/tb agents doctor` |
