# Examples — примеры

Переиспользуемые примеры и образцы: как у нас принято делать типовые вещи. Пассивный справочник —
его читают и копируют. Тип `example`, срок жизни — пока примеры актуальны.

## Когда создавать

- Один и тот же фрагмент (код, конфиг, запрос, текст) понадобился второй раз.
- Есть принятый в проекте образец, которого нет в одном очевидном месте Ресурсов.

## Когда не создавать

- Это процедура, которую Агент выполняет по шагам, — оформи skill в `.agents/skills/`.
- Хороший пример уже есть в коде — дай ссылку на файл (например, в карточке сущности).
- Фрагмент нужен один раз.

## Статус и удаление

Статуса у примеров нет: пример либо соответствует принятому подходу, либо его исправляют на месте.
Подход сменился и пример не нужен — удали заметку, а на замену дай ссылку там, где на пример ссылались.

Версии, к которым относится пример, — в `applies_to`: `[python@3.12, pytest@8]`.

## Имя и создание

Имя файла — что демонстрирует пример: `pytest-db-fixture.md`, `release-notes.md`.

`Toolbox/tb kb new example pytest-db-fixture --title "Фикстура тестовой БД в pytest"`

## Пример (фрагмент)

```markdown
title: "Фикстура тестовой БД в pytest"
description: "Транзакция на тест с откатом — без пересоздания схемы"
applies_to: [pytest@8, sqlalchemy@2]
## Когда применять
Интеграционные тесты сервисов, которые пишут в Postgres.
```
