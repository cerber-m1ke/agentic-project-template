# Знания

Постоянная память проекта: то, что нужно Агенту и человеку для работы и чего нет в Ресурсах и истории
git. Встроенная память агентов не используется — всё хранится здесь, под git, и не зависит от конкретного
Агента. Знания быстро устаревают и обрастают шумом, поэтому их регулярно ревьюят (skills `kb-review` и `plan-review`).

## Правила

- Храним только то, что нельзя восстановить из Ресурсов и истории git.
- Только живое: устаревшее исправляем на месте, отжившее удаляем. Прежние версии остаются в истории git,
  поэтому статусов вроде «устарело» или «заменено» нет.
- Одна заметка — одна тема. Сначала ищем существующую (`Toolbox/tb kb search`) и обновляем её, а не плодим дубликаты.
- Относительные даты («вчера», «в следующем месяце») превращаем в абсолютные: `2026-10-08`.
- Имена файлов — латиница, lowercase kebab-case: `uv-proxy-ssl.md`. Заголовок и текст — на языке проекта.
- Ссылки — относительные Markdown-ссылки: `[Выбор uv](../Decisions/use-uv-for-tools.md)`. Не `[[wikilinks]]`.
- Ссылка на заметку, которую ещё предстоит написать, — с title `"pending"` (подсказка ссылки):
  `[Кэш](../Gotchas/cache.md "pending")`. `Toolbox/tb kb lint` о ней предупреждает, но коммит не блокирует,
  а `Toolbox/tb kb stale` показывает заметку как кандидата на доработку. Цель появилась — уберите title `"pending"`.
- Никаких секретов (токенов, паролей, ключей) и реальных данных клиентов и пользователей: выгрузок,
  персональных данных.
- Индекс не ведём руками: `Toolbox/tb kb index` строит его из frontmatter.
- Пишет в Знания основной Агент (библиотекарь только читает); коммит — по просьбе человека (skill `kb-commit`).

## Типы заметок

| Тип | Каталог | Что хранит | Статусы | Срок жизни |
|---|---|---|---|---|
| `decision` | [Decisions](Decisions/README.md) | Архитектурные решения (ADR): контекст, решение, альтернативы, последствия | `proposed`, `accepted` | Пока действует |
| `entity` | [Entities](Entities/README.md) | Карточка сущности: назначение, где лежит, связи, неочевидное, владельцы | `active`, `deprecated` | Пока сущность жива |
| `example` | [Examples](Examples/README.md) | Переиспользуемые примеры и образцы — справочник | — | Пока актуальны |
| `gotcha` | [Gotchas](Gotchas/README.md) | Грабли: симптом, причина, обход, как проверить актуальность | — | Пока жива причина |
| `plan` | [Plans](Plans/README.md) | Идеи, отложенное, обнаруженное по ходу работы | `idea`, `ready` | До задачи или отказа |
| `task` | [Tasks](Tasks/README.md) | Текущая задача: цель, спецификация, решения по ходу, прогресс, итоги | `active`, `blocked`, `done` | До сбора итогов |

Конец срока жизни — удаление заметки: заменённое решение, устранённые грабли, неактуальный пример,
отвергнутый план, карточка выведенной сущности. Важное из удаляемого переносится в живую заметку
(например, почему отказались от прежнего решения — в «Альтернативы» нового).

Решения, принятые внутри задачи, живут в задаче и уходят вместе с ней. В Decisions попадают только те,
что переживают задачу.

## Frontmatter

```yaml
---
type: gotcha               # decision | entity | example | gotcha | plan | task
title: "uv не скачивает Python за прокси"
description: "Ошибка SSL при tb setup за корпоративным прокси"   # одна строка: по ней ищут и решают, открывать ли
# status: active           # у gotcha и example поля нет; у других типов значения зависят от типа
created: 2026-10-08
verified: 2026-10-08       # когда последний раз сверено с реальностью
tags: [uv, network]
aliases: [proxy, прокси]   # синонимы на русском и английском — для поиска
resources: [api, api/src/billing]   # имена из Resources/resources.toml, можно с подпутём
applies_to: [uv@0.12]      # только gotcha и example: к каким версиям относится
---
```

- Обязательны `type`, `title`, `description`, `created`; `status` — у всех типов, кроме gotcha и example.
- Ключи и значения перечислений — латиницей, даты — `ГГГГ-ММ-ДД`. Схему проверяет `Toolbox/tb kb lint`.
- `resources` — имя из каталога, можно с подпутём внутри ресурса (`api/src/billing`) и веткой (`api@main`).
  Если ресурс склонирован, lint проверяет, что подпуть существует. `--resource api` в поиске находит и
  `api/…`, `--resource api/src` — только этот подпуть. Карточку ресурса в `Entities/` укажите в поле
  `entity` каталога: lint проверяет, что файл существует, и подсказывает, если поле пустое.
- Сверили заметку с реальностью — `Toolbox/tb kb verify <путь|slug>`: ставит `verified` на сегодня, остальной
  текст не трогает, и проверяет заметку. `--date` — другая дата, `--dry-run` — только показать.

## Жизненный цикл

```
Plans (idea) ──► Tasks (active) ──► done ──► сбор итогов ──► удаление задачи
                                                 │
                             Decisions / Gotchas / Entities / Examples
```

Итоги собирает skill `wrap-up`; удалённая заметка остаётся в истории git. `Toolbox/tb kb stale` предлагает
перепроверить заметку, если `verified` (или `created`) старше порога: gotcha — 90 дней, entity
и example — 180, plan (`idea`, `ready`) — 60, task (`active`, `blocked`) — 30, decision (`proposed`) — 30.
Задача в статусе `done` попадает в список всегда: её итоги ещё не собраны. Заметка с упразднённым
статусом (`superseded`, `resolved`, `outdated`, `dropped`) — тоже: она отжила, её пора удалить.
Заметка с отложенными ссылками (`"pending"`) — тоже: её пора дописать.

## Команды

| Команда | Назначение |
|---|---|
| `Toolbox/tb kb search <запрос> [--type T] [--status S] [--resource R]` | Поиск по заголовкам, описаниям, синонимам, тегам и тексту |
| `Toolbox/tb kb show <путь\|slug>` | Заметка целиком |
| `Toolbox/tb kb related <путь\|slug>` | Ссылки и обратные ссылки |
| `Toolbox/tb kb new <type> <slug> --title "…" --description "…"` | Новая заметка из шаблона; `--folder` — задача-папка |
| `Toolbox/tb kb index` | Индекс, сгруппированный по типам |
| `Toolbox/tb kb lint` | Frontmatter, ссылки, имена файлов, каталог Ресурсов, бюджет `AGENTS.md` |
| `Toolbox/tb kb verify <путь\|slug>…` | Отметить сверку: `verified` на сегодня и проверка заметок |
| `Toolbox/tb kb stale` | Кандидаты на перепроверку и доработку |

На Windows (PowerShell) — `Toolbox\tb.cmd kb …`.

## Шаблоны

`_templates/` — шаблоны заметок, общие для `Toolbox/tb kb new` и Obsidian. Плейсхолдеры `{{title}}` и `{{date}}`
подставляются при создании заметки. Заметками шаблоны не считаются. Шаблоны принадлежат проекту: правьте
их под себя — обновление шаблона только предложит свои изменения.

## Obsidian

Корень хранилища — `Knowledge/`: откройте эту папку в Obsidian как хранилище (vault). `Toolbox/tb obsidian setup`
пишет конфигурацию: Markdown-ссылки вместо `[[wikilinks]]`, относительные пути, папка шаблонов `_templates`.
Каталог `.obsidian/` в git не попадает. Создавая заметку в Obsidian, давайте файлу имя в kebab-case,
вставьте шаблон нужного типа и замените `title` на человекочитаемый заголовок.
