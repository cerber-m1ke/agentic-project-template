# Entities — сущности

Карточки сущностей проекта: сервисов, библиотек, приложений, хранилищ, внешних систем. Что выделять
в сущность, решаем сами; одна сущность может охватывать несколько ресурсов. Тип `entity`, срок жизни —
пока сущность жива.

## Когда создавать

- О сущности спрашивают или её касаются регулярно, а быстро сориентироваться по коду трудно.
- Есть неочевидные связи, инварианты, исторические причины, владельцы.
- Ресурс из `Resources/resources.toml` — его карточка указывается в поле `entity` каталога.

## Когда не создавать

- Ради пересказа кода, API или README ресурса — дай ссылку на них.
- Для мелких единиц (класс, функция, эндпоинт) — это часть карточки более крупной сущности.

## Статусы

- `active` — сущность существует и используется.
- `deprecated` — выводится или выведена из работы; укажи замену. Когда ссылки на карточку исчезнут, её можно удалить.

## Имя и создание

Имя файла — имя сущности: `api.md`, `billing-service.md`, `postgres-main.md`. Для ресурса — совпадает
с его `name` в каталоге.

`Toolbox/tb kb new entity billing-service --title "Сервис биллинга"`

## Пример (фрагмент)

```markdown
title: "Сервис биллинга"
description: "Начисления и счета; единственный, кто пишет в таблицу invoices"
resources: [billing]
## Неочевидное
Суммы хранятся в копейках (int). Пересчёт за прошлый месяц запрещён после 5-го числа.
```
