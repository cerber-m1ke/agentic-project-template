# Ревью планов

## Цель и результат

Plans — короткий и живой бэклог. Каждый план актуален и не дублирует другие планы и задачи. По каждому
понятно, готов ли он к работе, а у человека есть предложенный порядок. Ревью закончено, когда:

- у каждого плана есть вердикт с обоснованием, у `delete` — с доказательством;
- подтверждённые действия применены, `Toolbox/tb kb lint` без ошибок;
- человек получил отчёт с приоритетами и вопросами.

## Границы

- Охват — `Knowledge/Plans/`. Остальные Знания проверяет skill `kb-review`.
- Задачи читаешь, чтобы найти пересечения, но не меняешь их — кроме переноса плана в задачу.
- Работу по плану не начинаешь. Создание задачи, удаление, объединение и смену статуса выполняй только
  после подтверждения человека.
- Проверка по Ресурсам — только чтение, как в `kb-review`.
- Не коммить: в конце предложи skill `kb-commit`.

## Вердикты

| Вердикт | Когда | Действие |
|---|---|---|
| `ready` | Выполнены критерии готовности | `status: ready`, `verified` = сегодня |
| `refine` | Идея жива, но критериям готовности не отвечает | Дописать известное, вопросы — человеку; `idea`, `verified` = сегодня |
| `to-task` | Готов, и человек берёт его в работу сейчас | `Toolbox/tb kb new task <slug>`, перенести содержимое, удалить план |
| `merge` | Пересекается с другим планом или покрыт активной задачей | Объединить в один план или дописать в задачу; лишнее удалить |
| `delete` | Уже сделано; неактуально (сменился подход, сущности нет); человек отказался | Удалить; важную причину отказа — решением в Decisions |
| `ask` | Нужен выбор человека или проверить нельзя | Конкретный вопрос |

## Критерии готовности

- Цель и польза — в 1–3 предложениях; понятно, как проверить результат.
- Оценён объём: мелочь на сессию или задача на несколько сессий.
- Затронутые ресурсы перечислены в `resources` и есть в каталоге.
- Известны первые шаги. Открытых вопросов нет или они записаны; блокеры названы.

## Доказательства

- «Уже сделано» — коммит или место в коде: `git -C Resources/<name> log --oneline --grep '<слово>'`
  или `-S '<строка>'`, `Resources/<name>/<путь>:<строка>`, `git log --oneline -- <путь>`.
- «Неактуально» — что изменилось: решение, удалённая сущность, новый подход; путь или коммит.
- «Покрыт задачей» — путь задачи и пункт её спецификации.
- Нет доказательства — `ask`.

## Порядок

1. **Сбор.** `Toolbox/tb kb search --type plan --brief`, `Toolbox/tb kb stale` (планы),
   `Toolbox/tb kb search --type task --status active,blocked --brief` — для пересечений
   (Windows PowerShell: `Toolbox\tb.cmd …`).
2. **Чтение.** Прочитай каждый план: `Toolbox/tb kb show <путь>`.
3. **Проверка.** Проверь по Ресурсам «сделано ли» и «актуально ли». Если планов больше восьми
   и агент умеет запускать субагентов, раздай проверку `kb-auditor` пачками по ресурсу, параллельно,
   с пометкой «skill plan-review».
4. **Вердикты.** Вынеси вердикты и найди пересечения: план с планом, план с задачей.
5. **Приоритеты.** Для `ready` и `refine` предложи порядок по критериям: польза, срочность (что
   блокирует), стоимость, зависимости. Порядок указывается только в отчёте, файлы планов ради него
   не меняются.
6. **Отчёт.** Покажи отчёт в формате ниже и дождись подтверждения. Спроси, какие планы брать в работу.
7. **Применение** — только подтверждённого. Затем `Toolbox/tb kb lint` без ошибок.
8. **Итог.** Числа по вердиктам, созданные задачи, открытые вопросы. Предложи skill `kb-commit`.

## Критерии приёмки

- Нет двух планов об одном и нет планов, покрытых активной задачей.
- `ready` стоит только у планов, которые отвечают критериям готовности.
- У оставленных планов `verified` = сегодня, поэтому `tb kb stale` их больше не показывает.
- Отжившие планы удалены, а важные причины отказа записаны.

## Формат отчёта

```
Ревью планов <ГГГГ-ММ-ДД> — планов: N
ready: N · refine: N · to-task: N · merge: N · delete: N · ask: N

| План | Вердикт | Обоснование / доказательство | Действие |
|---|---|---|---|

Предлагаемый порядок: 1. <план> — <почему первым>; 2. …
Вопросы к человеку:
1. …
```
