# Коммит Знаний

Только по просьбе человека. Коммит содержит только `Knowledge/`; остальные изменения коммитятся
отдельно, со своим scope и тоже по просьбе.

1. **Изменения.** `git status --porcelain -- Knowledge/` и `git diff -- Knowledge/`. Пусто — скажи
   об этом и закончи.
2. **Индекс.** `git diff --cached --name-only`. Если там уже есть файлы вне `Knowledge/` — не трогай
   их и спроси человека, как быть.
3. **Проверка Знаний.** `Toolbox/tb kb lint` (Windows PowerShell: `Toolbox\tb.cmd kb lint`).
   Ошибки исправь; спорное — спроси человека.
4. **Секреты.** `Toolbox/tb secrets scan <добавленные и изменённые файлы>`. Найдено — убери секрет из заметки.
   Не коммить, пока проверка не проходит.
5. **Сообщение.**
   ```
   knowledge: <суть одной строкой>

   - <тезис о содержании: что узнали, решили, изменили>
   - …
   ```
   Тезисы — о смысле, а не о файлах: «Gotcha: uv за прокси требует SSL_CERT_FILE», «Задача
   auth-token-refresh завершена, итоги перенесены в Entities/api».
6. **Подтверждение.** Покажи человеку список файлов и сообщение, дождись согласия.
7. **Индексация явных путей:** `git add -- Knowledge/Gotchas/uv-proxy-ssl.md Knowledge/Tasks/auth-token-refresh.md`.
   Удалённые файлы добавляются так же. Никогда `git add -A`, `git add .`, `git commit -a`.
   Убедись, что `git diff --cached --name-only` показывает только эти пути.
8. **Коммит.** Запиши сообщение в `Runtime/commit-msg.txt` и выполни `git commit -F Runtime/commit-msg.txt`,
   затем удали файл. Хук pre-commit повторит `kb lint` и поиск секретов: если он упал — исправь причину,
   `--no-verify` не используй.
9. **Отчёт:** хэш коммита (`git log -1 --oneline`) и список файлов.
