# Перенос проекта (adopt)

## Цель и результат

Всё ценное из старых мест — в Ресурсах и Знаниях, ничего не потеряно молча, старое удалено после GO
финального аудита. Перенос закончен, когда:

- у каждого файла каждого источника есть строка реестра с вердиктом и `ok` аудитора, `tb adopt gate`
  зелёный;
- финальный аудит дал GO, человек проверил новое окружение и подтвердил очистку;
- старое убрано по манифесту удаления, задача закрыта через `wrap-up`, модуль `adopt` снят.

Малый проект (несколько репозиториев, только память агентов) этот skill не требует: хватит INIT §6.

## Границы и безопасность

- Старые места (старые копии, хранилища, `~/.claude`, `~/.codex`) — только чтение до этапа 8, после —
  только по манифесту удаления. Удаление — в Корзину, которую человек очищает сам.
- Проверки — только чтением: без docker, сборки, тестов, `fetch`/`pull`/`checkout`, сети. Не проверить —
  `unverified` по `rules.md`.
- Значения секретов никуда не копируются: ни в заметки, ни в реестр, ни в ответы. В реестре — указатель
  `путь:строка — что это`. Проверяющие не выводят содержимое найденного: только путь, тип, размер, сумму.
- Необратимое и внешнее (переименование, `mv` ресурса, push, удаление) — только после «да» человека.
- Хук pre-commit не обходи: никаких `--no-verify` и `commit-tree`. Упал — чини причину.
- «Нет в коде» доказывает только поиск без учёта ignore-файлов: `rg --no-ignore`,
  `git -C <репозиторий> grep` по каждому вложенному репозиторию.

## Где что лежит

- Задача `Knowledge/Tasks/<задача>/` (создаёт `tb adopt start`), всё в git:
  - `index.md` — заметка задачи: цель, прогресс, решения, «Что в работе», замечания к шаблону;
  - `plan.md` — статус этапов и сессий, граф зависимостей, факты и решения проекта, раздел на этап;
  - `adopt.toml` — старые корни, каталог архива, папка секретов, источники `[[source]]`;
  - `rules.md` — правила проекта поверх базовых `.agents/skills/adopt/rules.md`;
  - `resources.md` — инвентаризация и решение по каждой строке;
  - `questions.md` — вопросы вне пачек; `ledger/<источник>/` — манифест и пачки;
  - `final-audit.md`, `deletion-manifest.md` — этап 7.
- `Runtime/adopt/` — сырьё вне git: инвентаризация, дайджесты, отчёты проверяющих.
- Каталог архива (`archive_dir`) — вне проекта, права 700, архивы 600.
- Промпты субагентов — `.agents/skills/adopt/prompts/`, заготовки — `.agents/skills/adopt/templates/`.

## Роли и контекст

- **Оркестратор** — основная сессия этапа: режет пачки, запускает субагентов, сводит, ведёт `index.md` и
  свою строку `plan.md`, задаёт вопросы, коммитит. Массово не читает: тела заметок и источники читают
  субагенты, оркестратор — отчёты `check`/`gate` и вердикты.
- **Рабочий** — субагент `adopt-worker`, одна пачка по `prompts/worker.md`.
- **Аудитор** — субагент `adopt-auditor`, свежий контекст, по `prompts/auditor.md`; пишет только колонку
  «Аудит». Оркестратор не вписывает вердикты аудита за аудитора.
- Пачка — до 12 файлов или ~60 КБ текста по одной теме или папке. Одновременно — не больше 5 субагентов.
  Ответ субагента — не длиннее 10 строк, подробности — в реестре.
- Нет субагентов — делай роли сам по тем же промптам, аудит — отдельным проходом после паузы на
  перечитывание `rules.md`.

## Сессии и возобновление

- Сессия = строка в `plan.md` (ID, зависимости, статус, дата, итог). Стартовый промпт сессии единый:
  «Выполни сессию <ID> по `plan.md` задачи <задача>; прочитай общие правила и свой раздел».
- Сессия правит только свою строку статуса, перечитав `plan.md` перед правкой.
- Точка продолжения — реестр и `plan.md`, а не память сессии: `tb adopt status`. У предела контекста
  остановись на границе пачки, запиши прогресс в `index.md` и закончи; следующая сессия с тем же
  промптом продолжает с первой непокрытой строки.
- Конец сессии: строка статуса, «Прогресс» в `index.md`, предложение коммита, ответ человеку ≤ 10 строк.

## Конвейер пачки

1. `tb adopt next <источник>` — непокрытые файлы с размерами; нарежь пачку по теме.
2. Рабочий (`prompts/worker.md`) → `tb adopt check <источник> <пачка> --pre-audit` зелёный.
3. Аудитор (`prompts/auditor.md`) → `ok` или `fix: …` по каждой строке.
4. `fix` — рабочий дорабатывает и очищает «Аудит», снова аудитор. Не больше 2 раундов, дальше — вопрос
   человеку.
5. Финал источника: `tb adopt check <источник>` зелёный, `duplicate-candidate` разобраны оркестратором
   (слил → `merged`/`duplicate`), непринятые передачи отданы пачкой `hNN` получателя.

Первая пачка каждого вида источника — пилот: человек смотрит пары «источник → результат» и утверждает
правила до остальных пачек.

## Параллельные сессии и коммиты

- Параллельно — по группе источников на сессию, в общем дереве проекта (worktree корня ресурсов не содержит).
- Сессия коммитит только свои заметки и свои файлы реестра, явными путями, после зелёного
  `check <источник>`. Ссылки на ещё не созданные заметки — отложенные (`"pending"`), их снимет
  `tb adopt links --write`.
- Общие файлы задачи и закрытие этапа коммитит оркестратор после зелёного `tb adopt gate`. Занят
  `index.lock` — повтори позже.

## Этапы

0. **Подготовка (до init — INIT §6.2).** Свежий бэкап машины; закрыты сессии агентов и IDE в старом пути;
   старая папка переименована, привязанное к пути перенесено; init `--with adopt`, ресурсы и adopt в init
   пропущены. Дальше этот skill: `tb adopt start <задача> --old-root <путь>… --archive-dir <путь>`,
   `plan.md` по заготовке, архив невосстановимого (хранилище без remote, рабочие документы, локальные
   репозитории без remote) — `tb adopt archive <имя> <пути…>`.
   Готово, если: задача и `plan.md` созданы, архивы сверены (`archive` проверил суммы).
1. **Инвентаризация.** `tb adopt inventory` (по `old_roots`), черновик — в `resources.md` задачи.
   Решение человека по каждой строке одним пакетом: `clone` (+ ветка), `mv` (состояние привязано к
   пути), `folder`, `secret`, `toolbox`, `knowledge` (уходит в перенос), `push-first` (человек пушит,
   затем `clone`), `archive` (git bundle или tar), `discard` (с причиной).
   Готово, если: решение у каждой строки, вся локальная работа (ветки, stash, грязное, устаревшие
   `origin/*`) учтена.
2. **Ресурсы.** `tb resources add <старая копия> --clone --entity …`; предупреждения о локальной работе
   сверь с `resources.md`, неучтённое — стоп и вопрос. Секреты — копированием в папку секретов
   (`secrets_dir`, права 700/600, скрыта в `.ignore`) со сверкой sha256. `mv` — по процедуре: снимок
   состояния, поиск абсолютных путей, «да» человека, остановка без потери данных, перенос, правка путей,
   проверка против снимка, описанный откат. Хвосты, которым нужна сеть, — первым шагом следующей
   сессии. Настройки агентов ресурсов (`.claude/`, `.mcp.json`, `.codex/`) разбирает субагент сводкой:
   MCP → `.agents/mcp.toml`, запреты → `.agents/permissions.toml`, процедуры → `.agents/skills/`, хуки →
   правила `AGENTS.md`; разобранное — `tb resources set <name> agent_settings_reviewed=…`. Инструкции
   агентов внутри ресурсов остаются на месте, но проверь их на секреты.
   Готово, если: `tb resources status` и `tb agents doctor` без замечаний.
3. **Правила и пилот.** `tb adopt sources` → блоки `[[source]]` в `adopt.toml` (транскрипты — только по
   запросу человека). Субагенты изучают по ~5 образцов каждой папки источника. `tb adopt manifest`,
   `tb adopt slugmap`, `rules.md` проекта (таблица ресурсов и тегов, решения человека, исключения).
   Пилот — 8–10 разнородных файлов через весь конвейер.
   Готово, если: человек утвердил правила по парам «источник → результат», `check` пилота зелёный.
4. **Перенос.** По источникам, параллельными сессиями, конвейером пачек. Транскрипты — последними и только
   по дайджестам: `tb adopt digest <источник>`, субагенты по ~8 дайджестов выдают кандидатов, человек
   утверждает список, затем рабочие создают заметки (остальные строки — `junk`/`derivable` с причиной).
   Готово, если: `check` каждого источника зелёный.
5. **Вопросы.** Раунд вопросов пакетом (`tb adopt status` собирает открытые), ответы — в заметки тем же
   конвейером, в строке вопроса — `(ответ: …)`. Повторяется после этапов 4, 6 и 7.
6. **Консолидация.** Дубли и пересечения между источниками; `tb adopt links --write` по всем Знаниям;
   skills `kb-review` и `plan-review` по всему (отчёты в файлы); `tb kb verify` по проверенному;
   проектная часть `AGENTS.md` (правила из инструкций и памяти — по согласию); `entity` в каталоге.
   «Что в работе» в `index.md`: активные задачи с ресурсами, ветками, push/MR и следующим шагом.
   Замечания к шаблону сведены по темам в `index.md`.
   Готово, если: `tb adopt gate` зелёный, `tb kb lint` 0/0, `tb secrets scan` чисто.
7. **Финальный аудит.** Только чтение, блоки — отдельными субагентами по `prompts/final-check.md`:
   A — Знания (полнота манифестов обратным обходом источников, переаудит 10% строк
   `obsolete`/`derivable`/`duplicate`/`junk`, не меньше 15); B — код (`tb adopt inventory --compare
   <снимок этапа 1>`, работа вне новых клонов); C — секреты; D — данные агентов; E — окружение
   (`tb adopt refs`); F — новое окружение (`tb setup`, `doctor`, ресурсы, Знания). Итог — `final-audit.md`
   с GO/NO-GO (при NO-GO у каждого блокера — сессия-исправление) и `deletion-manifest.md`.
   Готово, если: вердикт GO, манифест удаления составлен.
8. **Очистка** — только после GO и «да» человека. Сначала человек проверяет сам: Знания в Obsidian по
   типам; два-три вопроса новой сессии агента («что сейчас в работе?») — ответы должны идти из Знаний;
   ресурсы и окружение работают. Затем закрыть сессии и IDE в старых путях. Порядок: архив корневого
   репозитория старой копии и транскриптов (`tb adopt archive`); удаление по манифесту — каждая группа
   после «да» (человек переносит в Корзину или агент `mv` в Корзину ОС); правки конфигов из аудита;
   записи приложений агентов — через их интерфейс; транскрипт сессии-оркестратора — последним.
   Затем skill `wrap-up` задачи, снятие модуля (`agentic-update`, «убрать модуль adopt»: данные задачи
   останутся), замечания к шаблону — человеку для issue.
   Готово, если: старые места убраны по манифесту, новое окружение — единственное рабочее место.

## Команды

| Команда | Что делает |
|---|---|
| `tb adopt start <задача>` | папка задачи из заготовок, `adopt.toml` со старыми корнями |
| `tb adopt archive <имя> <пути…>` | tar.gz в каталог архива, права 600, сверка sha256 по каждому файлу |
| `tb adopt inventory [корни…]` | репозитории (с вложенными), локальная работа против сервера, stash, грязное, ценное неотслеживаемое, не-git; `--fetch`, `--offline`, `--compare` |
| `tb adopt sources` | кандидаты в `[[source]]` по старым корням и данным агентов |
| `tb adopt manifest [--source S]` | `ledger/<источник>/manifest.txt` |
| `tb adopt slugmap` | плановая заметка для каждого файла источников с `folder` |
| `tb adopt next <источник>` | непокрытые файлы с размерами |
| `tb adopt links [заметки…] [--write]` | `[[wikilinks]]` и старые ссылки → относительные; ещё не перенесённое — `"pending"` |
| `tb adopt check <источник> [пачка] [--pre-audit]` | реестр: покрытие ровно один раз, вердикты, цели, аудит; затем `tb kb lint` |
| `tb adopt gate` | все источники, передачи приняты, вопросы списком; перед общим коммитом |
| `tb adopt status` | где перенос: статус `plan.md`, покрытие, передачи, вопросы, секреты |
| `tb adopt refs [пути…]` | старые пути в окружении (git, агенты, shell, Obsidian, IDE, cron, Docker) |
| `tb adopt digest <источник>` | дайджесты транскриптов с маскировкой секретов → `Runtime/adopt/digests/` |

Правила переноса — `rules.md` рядом с этим файлом.
