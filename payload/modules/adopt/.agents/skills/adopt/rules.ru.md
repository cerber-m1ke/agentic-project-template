# Базовые правила переноса знаний

Для рабочих, аудиторов и оркестратора skill `adopt`. Основа — `Knowledge/README.md` и README папок; здесь —
только то, что относится к переносу. Правила проекта (ресурсы и теги, решения человека, исключения) —
в `rules.md` задачи: они дополняют эти и при расхождении главнее.

## Вердикты

Каждому файлу манифеста — ровно одна строка реестра с одним вердиктом:

| Вердикт | Смысл | Цель | Причина |
|---|---|---|---|
| `migrated` | Перенесено в новые заметки | заметки через запятую | при отклонении от slugmap — почему |
| `merged` | Влито в существующую заметку | заметка | — |
| `task` | Активная работа | `Knowledge/Tasks/<slug>.md` или `…/<slug>/index.md` | — |
| `secret` | Секрет целиком (ключ, профиль, пароли) | файл в папке секретов (`secrets_dir`) | — |
| `foreign` | Не относится к проекту | — | куда отдать; решает человек (вопрос) |
| `obsolete` | Неактуально: сделано, отменено, устарело | — | доказательство: коммит, путь, команда |
| `derivable` | Выводится из кода, конфигов, git, README | — | где именно |
| `duplicate` | Дубль | — | чего именно |
| `duplicate-candidate` | Возможный дубль заметки из другой пачки | та заметка | разбирает оркестратор; финальным не бывает |
| `junk` | Мусор: обрывки, пробы, служебные файлы | — | что это, коротко |

- Частично перенесено — вердикт по главному (`migrated`/`merged`), отброшенное — в «Причину» одной фразой.
- Несколько источников в одну заметку: первый — `migrated`, остальные — `merged` в неё.
- Цель `migrated` может быть вне Знаний: skill (`.agents/skills/<name>/SKILL.md`), инструмент
  (`Toolbox/<имя>` с записью в `Toolbox/README.md`), проектная часть `AGENTS.md`.
- Не смог проверить — не придумывай вердикт: перенеси с пометкой `unverified` или задай вопрос.

## Реестр

`ledger/<источник>/<пачка>.md`, пачка — `NN-<тема>` (`01-auth`), `pilot` или `hNN` (доработка передач).

```markdown
# <источник> / <пачка>

| Источник | Вердикт | Цель | Причина | Аудит |
|---|---|---|---|---|
| ~/Vaults/App/decisions/2026-03-01-auth-tokens.md | migrated | Knowledge/Decisions/auth-tokens.md | | ok |
| ~/Vaults/App/decisions/old-cache.md | obsolete | | `rg --no-ignore -n CacheV1 Resources/api` → пусто; удалено в `a1b2c3d` | ok |

## Передача

- #1 → <источник-получатель>: <строка его манифеста> — <факт с доказательством>

## Вопросы

- #1 <вопрос> — <контекст>

## Секреты

- #1 <путь>:<строка> — <что это>
```

- Колонки — по позиции: источник, вердикт, цель, причина, аудит. Заголовки — на языке проекта.
- «Источник» — строка манифеста дословно; «Цель» — пути от корня проекта через запятую.
- «Причина» — до ~400 знаков: главное доказательство (команда → результат), что отброшено,
  `unverified: …`. Подробности — в заметке.
- `|` внутри ячейки экранируется: `\|`.
- «Аудит» пишет только аудитор: `ok` или `fix: <замечание>`. Рабочий оставляет пустым и очищает после
  доработки.
- Id пункта раздела — `<источник>/<пачка>#<n>`; номера в пачке не переиспользуются.
- Проверка: `tb adopt check <источник> [<пачка>] [--pre-audit]`.

## Тип и папка

| Вид источника | Куда | Правило |
|---|---|---|
| `vault` | по папке-типу (`folder`) | Слои «Уточнено <дата>», «Пересмотрено» свернуть в текущее состояние; отказ — в «Альтернативы». Глоссарий: термин — `aliases` сущности, понятие с жизнью — entity, коллизия значений — gotcha, имя из кода — `derivable`; вердикт файла — `merged` со всеми целями. Индекс хранилища — `derivable` (`tb kb index`) |
| `docs` | по содержанию | Единица — живой остаток папки: сначала статус по git и коду. Сделано — `obsolete`/`derivable`, вынуть только «почему» (decision) и неочевидные грабли (gotcha). Живое — task или plan на папку + выделенные decision/gotcha. Процедура — skill. Вложения, пробы, разведочные скрипты — `junk`; исследования — по решению человека (архив или папка-ресурс) |
| `claude-memory` | по содержанию | Нарезать по темам. Статусы («не закоммичено», «в работе») сверить по git ресурса до записи. `MEMORY.md` — `derivable` (индекс) |
| `codex-memory` | по содержанию | Память глобальная: относящееся к проекту — как `claude-memory`, остальное — `foreign` |
| `agent-files` | — / `.agents/` | `settings.local.json` — `junk` после `tb secrets scan`. Команды, агенты, skills — вопрос: в `.agents/` или отбросить. `.git/info/exclude` — `obsolete` (игнор в новых клонах — этап 2). Корневые `CLAUDE.md`/`AGENTS.md` — правила работы с человеком в проектную часть `AGENTS.md` по согласию, остальное `obsolete`/`derivable` |
| `loose-docs` | — | `diff` с закоммиченной копией: совпало — `derivable` с путём и коммитом; отличается — вопрос с кратким диффом |
| `transcripts` | по дайджесту | Строка — сессия. Кандидат в заметку только по утверждённому человеком списку; остальное — `junk` («обычная работа, итог в git») или `derivable` |
| `instructions` | `AGENTS.md` | Правила работы с человеком, относящиеся к проекту, — в проектную часть `AGENTS.md` по согласию; общее — `foreign` |

Грабли:

- «Как проверить актуальность» — проверка без побочных эффектов (`rg -n`, `git log -S`, версия в
  lock-файле) и ожидаемый результат, пока причина жива. Проверить можно только на проде или во внешней
  системе — так и написать.
- `applies_to`: сторонний компонент — `<пакет>@<мажор.минор>` из lock-файла или манифеста; поведение
  своего кода — `<модуль>@<ГГГГ-ММ-ДД проверки>`.
- Исправимый дефект своего кода — plan «исправить», а не gotcha. Стороннее поведение и свой дефект в
  одном источнике делятся: gotcha + plan со ссылкой на неё.
- «Починено», «неактуально» в тексте — повод проверить первыми, но не доказательство.

Планы и сущности:

- Plan `ready` — если ясно, с чего начать; иначе `idea`. Многотемный план делится; история
  («Пересмотрено», «Что закрыто») не переносится. Статус проверять на ветке, которую план называет.
- Сущность: «Назначение» в 1–3 фразы + ссылка на README/`AGENTS.md` ресурса; стек, сборка, тесты,
  текущее состояние — `derivable` или Tasks; ограничения — в «Неочевидное». Абсолютные пути убрать.
  Тонкая карточка без неочевидного — `derivable`.
- Сущности и решения не ссылаются на планы: связь — ссылкой из плана.
- Решения задачи — в «Решения по ходу» задачи, а не в Decisions.
- Скрипт, на который опирается живая заметка или который нужен регулярно, — в `Toolbox/` или ресурс
  (вопрос человеку); разовые пробы — `junk`. Вложение — единственная копия кода: в заметке — где лежит
  (архив) и вопрос, куда сохранить.

## Имя заметки

- slug — по `slugmap.md`: имя файла без даты-префикса `ГГГГ-ММ-ДД-` (дата — в `created`), транслит,
  kebab-case. Отклонение (другая папка, деление, слияние) — в «Причине».
- Новые заметки при делении — латиница, kebab-case, суть темы.
- Сущность — по имени ресурса в каталоге или каталога модуля.
- Создание — только `tb kb new <type> <slug> --title "…" --description "…"`.

## Frontmatter

| Было | Стало |
|---|---|
| `title`, H1 | `title` на языке проекта |
| `date`, дата в имени, первый коммит файла | `created` |
| — | `verified` — сегодня, если ключевые утверждения сверены с `Resources/`; иначе — дата источника и тег `unverified` |
| — | `description` — одна строка, суть, не повтор заголовка |
| — | `status`: decision — `accepted`, если код соответствует (доказательство в реестре), иначе `proposed` + вопрос; plan — `idea`/`ready`; entity — `active`/`deprecated`; task — `active`/`blocked` |
| служебные поля (`project`, `tags: [decision]`, `metadata`) | отбросить |
| `area` и подобное | `resources` (имена из каталога, `<ресурс>/<подпуть>` для модулей) + `tags` — по `rules.md` задачи |
| синонимы, термины глоссария | `aliases` |
| версии в тексте грабель | `applies_to` |

## Тело

- По разделам шаблона типа. Текущее состояние, а не хронология.
- Не переносить: пересказ кода, `файл:строка`, таблицы «где что лежит», хеши и номера тикетов без
  «почему», замеры и пробы, прогресс сделанной работы.
- Язык — язык проекта; заметки на другом языке переводятся.

## Ссылки

- Вместо `[[wikilinks]]` — относительные Markdown-ссылки: `tb adopt links <заметки> --write` (по реестру,
  затем по `slugmap.md`). Отчёт `UNKNOWN` — исправить руками (ссылка или текст).
- Цель ещё не перенесена — отложенная ссылка `[Текст](../Entities/api.md "pending")`: lint
  предупреждает, коммит не блокирует. Цель появилась — `links --write` снимет `"pending"`. Финал
  источника и этап 6 — `links --write` по всем Знаниям.
- Цель с вердиктом `obsolete`/`derivable`/`junk` — ссылка становится текстом.
- Ссылки на код — относительные на `Resources/<name>/<путь>`; абсолютные пути старых копий — заменить или
  убрать. Внешние URL — только постоянные.

## Даты

- Только абсолютные `ГГГГ-ММ-ДД`; `дд.мм` без года — год из контекста источника.
- «Сегодня», «сейчас» — переформулировать без даты или «на <дата источника>». Механическая замена запрещена.

## Актуальность и выводимость

- **`derivable`**: то же читается из кода, конфигов, CI, схемы БД, README, истории git — указать место.
  Остаётся «почему» или неочевидное — переносится только оно.
- **Актуально**: 1–3 ключевых утверждения (пути, символы, ключи, версии, ветки, «сделано») сверены с
  `Resources/` по правилам `kb-review` («Доказательства»). Главное: decision — соответствует ли код;
  gotcha — жива ли причина; plan — не сделан ли; entity — существует ли и где.
- **Не проверено** (ресурса нет, нужна сеть, прод или запуск):
  - главное не сверено — тег `unverified`, `verified` = дата источника;
  - сверено главное, но не второстепенное — `verified` = сегодня, в тексте «(со слов источника, не
    проверено)»;
  - в «Причину» — `unverified: <что именно>`.
- Команда-доказательство — ровно та, что выполнена, с результатом; поиск — по точной строке.
- Паттерн из одного модуля ищется и в соседних: охват заметки — по факту.
- Каждый упомянутый путь и символ проверяется на существование: в заметку идёт символ, не `путь:строка`.
- Опровергнуто кодом — исправить на факт; неясно, что верно, — вопрос, decision — `proposed`.

## Секреты и чувствительное

- Значения паролей, токенов, ключей (и dev-, и «публичных») никуда не копируются. В заметке — указатель:
  где лежит (папка секретов, хранилище секретов, файл в коде).
- Находка — пунктом раздела «Секреты» пачки: `- #N <путь>:<строка> — <что это>`. Файл целиком
  секретный — вердикт `secret` (копии в папке секретов нет — вопрос).
- Не переносить персональные данные, данные клиентов, IP и имена хостов инфраструктуры — обобщать.
- Перед сдачей пачки — `tb adopt check … --pre-audit` (включает `tb kb lint` с поиском секретов).

## Дубли

- Перед созданием — `tb kb search "<тема>"` (и по aliases). Заметка своей пачки — `merged`.
- Заметка другой пачки или сессии — не правь её: `duplicate-candidate` с её путём в «Цели»; разбирает
  оркестратор в финале источника.

## Передача фактов между источниками

- Факт нужен заметке, которую делает другая пачка или сессия, — не вписывай его в «Причину», а добавь
  пункт раздела «Передача» своей пачки: `- #N → <источник>: <строка манифеста получателя> — <факт с
  доказательством>`.
- Рабочий получателя переносит факт и пишет в своей пачке (раздел «Передача» или под таблицей)
  `принято: <id> → <заметка>` или `принято: <id> → — <почему не нужно>`.
- `tb adopt check` показывает непринятые передачи источнику: в пачке — предупреждением, в финале
  источника — ошибкой; `gate` — ошибкой. Непринятые для уже готового источника — доработочная пачка `hNN`.

## Вопросы

- Пункт раздела «Вопросы» пачки: `- #N <вопрос> — <контекст>`; вопросы вне пачек — в `questions.md`
  задачи в том же формате. Ответ — в той же строке: `(ответ: …)`.
- Оркестратор задаёт открытые вопросы человеку пакетом (`tb adopt status`) и вносит ответы в заметки и
  реестр тем же конвейером. `foreign` до ответа проходит аудит с `ok`.
