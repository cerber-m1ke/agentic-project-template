# Ресурсы

Ресурсы — то, над чем работаем в проекте: git-репозитории (код, документация, скрипты) или обычные
папки (документы, данные). Содержимое и порядок внутри ресурсов шаблон не регламентирует.

## Каталог и личный набор

- `resources.toml` — каталог всех известных ресурсов проекта. Хранится в корневом git; поля описаны
  в комментариях в начале файла.
- `Resources/<name>/` — локальные ресурсы. В корневой git они не попадают (`.gitignore`).
- У каждого человека может быть склонирован любой поднабор каталога — это нормально.

## Виды ресурсов

- `kind = "git"` — отдельный репозиторий со своей историей. Клонируется командой `Toolbox/tb resources clone`;
  коммиты — внутри него: `git -C Resources/<name> …`.
- `kind = "folder"` — обычная папка без git: документы, выгрузки, крупные и бинарные данные. Её
  содержимое не версионируется корневым git; откуда его брать — в `url` или в карточке ресурса.

## Команды

| Команда | Назначение |
|---|---|
| `Toolbox/tb resources status` | Что есть локально, текущая ветка, есть ли изменения |
| `Toolbox/tb resources clone <name>…` | Склонировать ресурсы из каталога; `--all` — все; `<name> --from <путь>` — из локальной копии, пока upstream недоступен (`origin` — url каталога) |
| `Toolbox/tb resources add <url> [--name N] [--branch B] [--kind git\|folder] [--description "…"] [--entity <путь>] [--clone]` | Добавить ресурс в каталог (с `--clone` — сразу склонировать). Путь к локальной рабочей копии записывает её `origin` и предупреждает о работе, которая есть только в этой копии; если upstream недоступен, `--clone` клонирует саму копию |
| `Toolbox/tb resources set <name> <поле>=<значение>…` | Изменить или добавить поле записи каталога, не трогая остальной текст и комментарии; `<поле>=` удаляет поле. Поля: `kind`, `url`, `branch`, `description`, `entity`, `agent_settings_reviewed` (через запятую) |
| `Toolbox/tb setup --clone-missing` | Склонировать все недостающие ресурсы |

На Windows (PowerShell) — `Toolbox\tb.cmd resources …`.

## Правила для Агента

- Задаче нужен ресурс, которого нет локально, — предложи человеку `Toolbox/tb resources clone <name>`.
- Если в ресурсе есть свои `AGENTS.md` или `CLAUDE.md` (в корне или в рабочем подкаталоге), прочитай их
  перед работой: внутри ресурса действуют его правила, а разные агенты подхватывают вложенные инструкции
  по-разному. Эти файлы принадлежат ресурсу — не меняй их без просьбы.
- Настройки агентов в ресурсе (`.claude/settings.json`, `.mcp.json`, `.codex/`, `.claude/skills`, …) агент,
  запущенный из корня проекта, не загружает: его хуки, разрешения и MCP-серверы не действуют.
  `tb resources status` и `tb agents doctor` их перечисляют. Нужное проекту переносится в `.agents/`
  (`permissions.toml`, `mcp.toml`, `skills/`, `hooks/hooks.toml`). Разобранные пути человек отмечает в поле
  `agent_settings_reviewed` (`Toolbox/tb resources set <name> agent_settings_reviewed=…`): о них предупреждений
  больше нет, о новых — есть.
- Коммиты в ресурс-репозиторий — только внутри него и только по просьбе человека. Содержимое ресурсов
  в корневой репозиторий не попадает.
- Задача перечисляет затронутые ресурсы в поле `resources` (имена из каталога).
- Знания о ресурсе — в карточке `Knowledge/Entities/<name>.md`; путь к ней — поле `entity` в каталоге.
  Пересказ содержимого ресурса в Знания не пишем.

## Поиск

`Resources/*` исключён из корневого git, и поиск, уважающий `.gitignore`, ресурсы не видит.

- ripgrep (`rg`) читает `.ignore` в корне проекта: правило `!/Resources/*` возвращает ему ресурсы.
- Вложенный git-репозиторий внутри ресурса, перечисленный в его `.gitignore`, ripgrep от корня не видит:
  `!/Resources/*` действует только на первом уровне. Верни его точечным правилом в проектной части `.ignore`
  корня (под блоком шаблона): `!/Resources/<ресурс>/<путь>/`. Иначе ищи внутри него: `git -C <путь> grep …`,
  `rg` из его каталога — или `rg --no-ignore`.
- Поиск, учитывающий только `.gitignore` (например, `grep` в оболочке Claude Code — обёртка над ugrep),
  не видит `Resources/` от корня вообще. Ищи из каталога ресурса или через `rg`.
- Пустой результат такого поиска — не доказательство отсутствия. Перед утверждением «нигде не используется»
  повтори поиск без учёта ignore-файлов: `rg --no-ignore …`, `git -C <репозиторий> grep …` или
  `command grep -r …` по нужному каталогу.
