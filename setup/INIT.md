# Инициализация проекта из шаблона

Инструкция Агенту. Цель — превратить свежий клон шаблона в Agentic Project и наполнить его
содержательной частью. Архитектура — `setup/DESIGN.md` §6.1–6.2.

- Прочитай инструкцию до конца до запуска init: init удалит `setup/` вместе с этим файлом.
- С человеком говори на его языке; после выбора языка проекта — на языке проекта.
- Ничего необратимого без явного «да» человека.
- Windows: `init.cmd` вместо `./init.sh`, `Toolbox\tb.cmd` вместо `Toolbox/tb` (в Git Bash работает
  и `Toolbox/tb`).

## 1. Предусловия

Проверь и сообщи человеку, если что-то не так:

- Это свежий клон шаблона, который станет проектом, а не рабочая копия для разработки шаблона: есть
  `setup/init.py`, `payload/`, `init.sh`. Сомневаешься — спроси: init заменяет `.git`. Клон внутри
  другого Agentic Project (например, `Resources/<name>/`) — ресурс, не проект: init откажется.
- `git status --porcelain` пуст.
- Заданы `git config user.name` и `git config user.email` (глобально или в этом клоне — локальные init
  перенесёт в новый репозиторий): init делает первый коммит.
- Клон — релиз: `git describe --tags --exact-match` печатает `v<версия>`, а `setup/VERSION` без `-dev`.
  Иначе это состояние разработки: init предупредит, проект получит релиз позже обновлением. Для реального
  проекта предложи `git checkout v<последний релиз>` (теги — `git tag --list "v*"`).
- Есть интернет: при первом запуске скачиваются uv и Python в `Runtime/`.
- Проверь, не займёт ли проект путь старого проекта (вопрос 8 интервью, §2).

## 2. Интервью

Спроси коротко, одним сообщением, предложи значения по умолчанию:

1. **Имя проекта** — по умолчанию имя папки.
2. **Язык** `ru` (по умолчанию) или `en` — на нём будут все документы и инструкции проекта.
3. **Профиль:**
   - `software` (по умолчанию) — проекты с кодом, ресурсы — git-репозитории;
   - `generic` — проекты без кода (документация, исследования, данные), ресурсы — чаще обычные папки.
4. **Модули:**
   - `obsidian` (включён) — настройка Obsidian для просмотра `Knowledge/`; не нужен → `--without obsidian`;
   - `devcontainer` (выключен) — контейнер для запуска Агента в песочнице; нужен → `--with devcontainer`.
5. **Агенты на этой машине:** `claude` (Claude Code), `codex` (Codex) — для каких создать адаптеры.
6. **Ресурсы:** URL репозиториев или источники папок, по одной строке описания на каждый; клонировать
   ли сейчас. Или «позже» — отдельным этапом после init (§6.1).
7. **Adopt:** есть ли уже локальные копии этих репозиториев и личные знания о проекте (память агентов,
   заметки)? Где лежат копии? Или «позже» (§6.1) — для большого проекта: много репозиториев, накопленная
   память и заметки.
8. **Путь:** займёт ли проект путь старого проекта (старую папку переименуют)? Да — остановись, выполни §6.2,
   init — в новом клоне.

## 3. Сводка и подтверждение

Покажи человеку:

- параметры и итоговую команду init;
- ресурсы и что из них будет склонировано; что отложено на отдельный этап;
- предупреждение: **история шаблона будет заменена новым git-репозиторием**, файлы инсталлятора
  (`setup/`, `payload/`, `init.*`, README и CHANGELOG шаблона) удалены. URL шаблона сохранится
  в `.agents/agentic.lock` для будущих обновлений.

Жди явного подтверждения. При сомнениях сначала покажи план: та же команда с `--dry-run` вместо `--yes`.

## 4. Запуск init

```sh
./init.sh --name <name> --language <ru|en> --profile <software|generic> --agents <claude,codex> --yes
```

Добавь `--with devcontainer` / `--without obsidian` по ответам. Windows — `init.cmd` с теми же флагами.

Init сделает коммит `agentic: init from template vX.Y.Z` и запустит `Toolbox/tb setup`. При ошибке покажи
сообщение человеку и устрани причину; не обходи init ручным удалением `.git` или копированием файлов.
Сообщение об ошибке говорит, как восстановиться. Предупреждения init (версия разработки, незакоммиченные
остатки папки шаблона) перескажи человеку.

После init в корне — `AGENTS.md` проекта. Шаги ниже выполняй в текущей сессии. Новые skills и хуки
агент может подхватить только в новой сессии — в конце предложи человеку перезапустить агента.

## 5. Содержательная часть

1. **`AGENTS.md`:** вне маркеров `agentic:begin`/`agentic:end` допиши 2–3 строки о проекте (что делаем,
   для кого, главные Ресурсы) и, если есть, особенности проекта в конце. Блок между маркерами не правь.
   Весь файл — не больше ~1500 токенов: подробности — в Знания.
2. **Ресурсы:** для каждого:

   ```sh
   Toolbox/tb resources add <url> --description "<одна строка>" --clone
   ```

   Без `--clone`, если клонировать не нужно; `--name`, `--branch` — если имя или ветка не по умолчанию;
   `--kind folder` — для ресурса-папки (она не версионируется и существует только на этой машине — скажи
   человеку, откуда её брать на других). Проверь: `Toolbox/tb resources status`.
3. **Entities** для главных ресурсов:

   ```sh
   Toolbox/tb kb new entity <slug> --title "<Название>" --description "<одна строка>"
   ```

   Заполни по README сущностей (`Knowledge/Entities/README.md`): назначение, где лежит, связи,
   неочевидные инварианты, владельцы — не пересказ кода. Прежде прочитай `AGENTS.md`/`CLAUDE.md`/README
   ресурса. Путь к заметке запиши в каталог командой, а не правкой `Resources/resources.toml`:
   `Toolbox/tb resources set <name> entity=Knowledge/Entities/<slug>.md`. Карточка готова до добавления
   ресурса — сразу `tb resources add … --entity Knowledge/Entities/<slug>.md`.

## 6. Adopt: обёртывание существующих репозиториев

- Репозитории **клонируй заново** в `Resources/` (`tb resources add … --clone`). Старые копии не переноси
  и не копируй в `Resources/`: от абсолютного пути зависят история и память агентов, настройки IDE. Старые
  копии остаются, пока человек сам их не уберёт. Переименование старого проекта целиком, чтобы новый занял
  его путь, — отдельный сценарий (§6.2).

### 6.1. Отложенный adopt

Большой проект (много репозиториев, накопленная память и заметки) за одну сессию не обернуть. Если
человек выбрал «позже»:

- В init и §5 — только `AGENTS.md` и главные ресурсы (или ни одного).
- Заведи задачу: `Toolbox/tb kb new task adopt --title "Adopt: ресурсы и личные знания" --description "…"`.
  В ней — репозитории с URL и путями старых копий, источники личных знаний, порядок (по ресурсу или группе
  за сессию), что уже сделано. Закоммить её в §7 вместе с остальным.
- Init удалит этот файл, поэтому перенеси в задачу и порядок §6.3: свежий клон
  (`tb resources add <путь старой копии> --clone`), разбор настроек агентов в ресурсах, сбор личных знаний
  (пути памяти Claude Code и Codex), раскладка по типам Знаний после подтверждения человека.
- Этап ведут по задаче в следующих сессиях и отмечают в ней прогресс.

### 6.2. Новый проект на месте старого (тот же путь)

Человек хочет, чтобы проект жил по пути старого (например, `~/src/app`), а старая папка уходит в архив.
Выполни до init, каждый шаг — с согласия человека:

1. **Страховка.** Закоммить и запушь всё нужное в старой папке или сделай её архив. Закрой IDE и сессии
   агентов, открытые в ней.
2. **Переименуй старую папку** целиком, например `~/src/app` → `~/src/appOld`. Это не перенос копии в
   ресурсы: старый проект остаётся целым, меняется только его путь.
3. **Перенеси привязанное к абсолютному пути** — само оно не переедет:
   - история и память Claude Code: каталог `~/.claude/projects/<закодированный путь>/` (кодировка — в
     «Сборе личных знаний» ниже) переименуй под новый путь старой копии (`…-src-app` → `…-src-appOld`).
     Иначе её история и память окажутся у нового проекта;
   - `includeIf "gitdir:…"` в `~/.gitconfig`, который подключает файл настроек из старой папки: вынеси
     файл (например, в `~/.gitconfig-<имя>`) и поправь `path`. Условие `gitdir:` старого пути теперь
     совпадёт с новым проектом и его ресурсами — спроси человека, нужно ли это; для старой копии добавь
     условие с её новым путём;
   - сессии Codex (`~/.codex/sessions/`) хранят рабочий каталог внутри файлов и переименованием не
     переносятся: останутся у прежнего пути, то есть у нового проекта. Не правь их, при желании —
     заархивируй;
   - настройки IDE вне папки (недавние проекты, рабочие области) — открыть старую копию заново по новому
     пути.
4. **Init на освободившемся пути.** Если этот клон шаблона лежит не там, склонируй шаблон в освобождённый
   путь (`git clone <URL шаблона> <путь>`, тот же тег) и попроси человека открыть в нём новую сессию
   агента; дальше — эта инструкция с §1 в новом клоне.

Старая копия дальше — источник для §6.3: `tb resources add <путь старой копии> --clone`, память Claude Code —
из переименованного каталога.

### 6.3. Обёртывание

- Можно передать путь к старой копии: `tb resources add <путь> --clone` запишет в каталог её `origin`
  и склонирует из него, а о незакоммиченном, незапушенном и stash в старой копии предупредит — это
  в свежий клон не попадёт, перескажи человеку. Копия без `origin` — спроси URL upstream. Upstream
  недоступен (VPN, локальный GitLab) — `--clone` склонирует саму копию и выставит `origin` на upstream;
  скажи человеку выполнить `git -C Resources/<name> fetch --prune origin`, когда upstream станет доступен.
- `AGENTS.md`, `CLAUDE.md`, `.claude/` внутри репозиториев остаются как есть: они принадлежат репозиторию.
- **Настройки агентов в ресурсах** (`.claude/settings.json`, `.mcp.json`, `.codex/`, `.claude/skills`
  и т.п.) агент, запущенный из корня проекта, не загружает — их перечисляет `tb resources status`.
  Разбери с человеком: MCP-серверы — в `.agents/mcp.toml`, общие процедуры — в `.agents/skills/`, хуки
  форматтеров и линтеров — в правила `AGENTS.md` (проверки ресурса запускаются перед коммитом в него).
- **Сбор личных знаний** (только чтение, источники не меняй):
  - память Claude Code: `~/.claude/projects/<путь старой копии>/memory/`, где в абсолютном пути каждый
    символ, кроме латинских букв и цифр, заменён на `-`: `/Users/me/src/my_api.v2` →
    `~/.claude/projects/-Users-me-src-my-api-v2/memory/`. Не нашёл (кириллица, Windows —
    `%USERPROFILE%\.claude\projects\`) — найди каталог, имя которого заканчивается на имя папки копии;
  - память Codex: `~/.codex/memories/`;
  - заметки и личные инструкции, на которые укажет человек (из глобальных — только относящееся к проекту).
- Разложи найденное по типам Знаний (Decisions, Entities, Examples, Gotchas, Plans, Tasks). Оставь только
  то, что не выводится из кода и истории git и всё ещё верно. Одна заметка — одна тема, относительные даты
  → абсолютные, никаких секретов.
- Покажи человеку список: тип, slug, заголовок, источник; что отброшено и почему. После подтверждения
  создай заметки через `Toolbox/tb kb new <type> <slug> --title "…" --description "…"` и заполни их
  (поле `resources` — имена из каталога).

## 7. Проверка и коммит

1. `Toolbox/tb agents doctor` и `Toolbox/tb kb lint` — исправь ошибки.
2. Покажи человеку итог: что создано, что осталось сделать (например, `git remote add origin <url>` —
   по желанию; `Toolbox/tb setup` на других машинах).
3. Предложи коммит. Только после согласия, только явные пути (не `git add -A`):
   - `agentic: <суть>` — `AGENTS.md`, `Resources/resources.toml`;
   - `knowledge: <суть>` — `Knowledge/`.

   В теле — ключевые тезисы.
4. Предложи перезапустить агента, чтобы подхватились skills и хуки проекта.
