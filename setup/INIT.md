# Инициализация проекта из шаблона

Инструкция Агенту. Цель — превратить свежий клон шаблона в Agentic Project и наполнить его
содержательной частью. Архитектура — `setup/DESIGN.md` §6.1–6.2.

- Прочитай инструкцию до конца до запуска init: init удалит `setup/` вместе с этим файлом.
- С человеком говори на его языке; после выбора языка проекта — на языке проекта.
- Ничего необратимого без явного «да» человека.
- Windows: `init.cmd` вместо `./init.sh`, `Toolbox\tb.cmd` вместо `Toolbox/tb` (в Git Bash работает
  и `Toolbox/tb`).

## 1. Предусловия

Проверь и сообщи человеку, если что-то не так:

- Это свежий клон шаблона, который станет проектом, а не рабочая копия для разработки шаблона: есть
  `setup/init.py`, `payload/`, `init.sh`. Сомневаешься — спроси: init заменяет `.git`.
- `git status --porcelain` пуст.
- Заданы `git config user.name` и `git config user.email`: init делает первый коммит.
- Есть интернет: при первом запуске скачиваются uv и Python в `Runtime/`.

## 2. Интервью

Спроси коротко, одним сообщением, предложи значения по умолчанию:

1. **Имя проекта** — по умолчанию имя папки.
2. **Язык** `ru` (по умолчанию) или `en` — на нём будут все документы и инструкции проекта.
3. **Профиль:**
   - `software` (по умолчанию) — проекты с кодом, ресурсы — git-репозитории;
   - `generic` — проекты без кода (документация, исследования, данные), ресурсы — чаще обычные папки.
4. **Модули:**
   - `obsidian` (включён) — настройка Obsidian для просмотра `Knowledge/`; не нужен → `--without obsidian`;
   - `devcontainer` (выключен) — контейнер для запуска Агента в песочнице; нужен → `--with devcontainer`.
5. **Агенты на этой машине:** `claude` (Claude Code), `codex` (Codex) — для каких создать адаптеры.
6. **Ресурсы:** URL репозиториев или источники папок, по одной строке описания на каждый; клонировать
   ли сейчас.
7. **Adopt:** есть ли уже локальные копии этих репозиториев и личные знания о проекте (память агентов,
   заметки)? Где лежат копии?

## 3. Сводка и подтверждение

Покажи человеку:

- параметры и итоговую команду init;
- ресурсы и что из них будет склонировано;
- предупреждение: **история шаблона будет заменена новым git-репозиторием**, файлы инсталлятора
  (`setup/`, `payload/`, `init.*`, README и CHANGELOG шаблона) удалены. URL шаблона сохранится
  в `.agents/agentic.lock` для будущих обновлений.

Жди явного подтверждения. При сомнениях сначала покажи план: та же команда с `--dry-run` вместо `--yes`.

## 4. Запуск init

```sh
./init.sh --name <name> --language <ru|en> --profile <software|generic> --agents <claude,codex> --yes
```

Добавь `--with devcontainer` / `--without obsidian` по ответам. Windows — `init.cmd` с теми же флагами.

Init сделает коммит `agentic: init from template vX.Y.Z` и запустит `Toolbox/tb setup`. При ошибке покажи
сообщение человеку и устрани причину; не обходи init ручным удалением `.git` или копированием файлов.

После init в корне — `AGENTS.md` проекта. Шаги ниже выполняй в текущей сессии. Новые skills и хуки
агент может подхватить только в новой сессии — в конце предложи человеку перезапустить агента.

## 5. Содержательная часть

1. **`AGENTS.md`:** вне маркеров `agentic:begin`/`agentic:end` допиши 2–3 строки о проекте (что делаем,
   для кого, главные Ресурсы) и, если есть, особенности проекта в конце. Блок между маркерами не правь.
   Весь файл — не больше ~1500 токенов: подробности — в Знания.
2. **Ресурсы:** для каждого:

   ```sh
   Toolbox/tb resources add <url> --description "<одна строка>" --clone
   ```

   Без `--clone`, если клонировать не нужно; `--name`, `--branch` — если имя или ветка не по умолчанию;
   `--kind folder` — для ресурса-папки. Проверь: `Toolbox/tb resources status`.
3. **Entities** для главных ресурсов:

   ```sh
   Toolbox/tb kb new entity <slug> --title "<Название>"
   ```

   Заполни по README сущностей (`Knowledge/Entities/README.md`): назначение, где лежит, связи,
   неочевидные инварианты, владельцы — не пересказ кода. Прежде прочитай `AGENTS.md`/`CLAUDE.md`/README
   ресурса. Путь к заметке пропиши в поле `entity` ресурса в `Resources/resources.toml`.

## 6. Adopt: обёртывание существующих репозиториев

- Репозитории **клонируй заново** в `Resources/` (`tb resources add … --clone`). Старые копии не перемещай
  и не копируй: от абсолютного пути зависят история и память агентов, настройки IDE. Старые копии
  остаются, пока человек сам их не уберёт.
- Перед клонированием проверь старые копии: незакоммиченное (`git -C <путь> status --short`)
  и незапушенное (`git -C <путь> log --branches --not --remotes --oneline`) в свежий клон не попадёт —
  скажи об этом человеку.
- `AGENTS.md`, `CLAUDE.md`, `.claude/` внутри репозиториев остаются как есть: они принадлежат репозиторию.
- **Сбор личных знаний** (только чтение, источники не меняй):
  - память Claude Code: `~/.claude/projects/<абсолютный путь старой копии, / заменены на ->/memory/`,
    например `/Users/me/src/api` → `~/.claude/projects/-Users-me-src-api/memory/`. Нет такого каталога
    (или Windows, `%USERPROFILE%\.claude\projects\`) — найди каталог, имя которого кодирует путь копии;
  - память Codex: `~/.codex/memories/`;
  - заметки и личные инструкции, на которые укажет человек (из глобальных — только относящееся к проекту).
- Разложи найденное по типам Знаний (Decisions, Entities, Examples, Gotchas, Plans, Tasks). Оставь только
  то, что не выводится из кода и истории git и всё ещё верно. Одна заметка — одна тема, относительные даты
  → абсолютные, никаких секретов.
- Покажи человеку список: тип, slug, заголовок, источник; что отброшено и почему. После подтверждения
  создай заметки через `Toolbox/tb kb new <type> <slug> --title "…"` и заполни их (поле `resources` —
  имена из каталога).

## 7. Проверка и коммит

1. `Toolbox/tb agents doctor` и `Toolbox/tb kb lint` — исправь ошибки.
2. Покажи человеку итог: что создано, что осталось сделать (например, `git remote add origin <url>` —
   по желанию; `Toolbox/tb setup` на других машинах).
3. Предложи коммит. Только после согласия, только явные пути (не `git add -A`):
   - `agentic: <суть>` — `AGENTS.md`, `Resources/resources.toml`;
   - `knowledge: <суть>` — `Knowledge/`.

   В теле — ключевые тезисы.
4. Предложи перезапустить агента, чтобы подхватились skills и хуки проекта.
