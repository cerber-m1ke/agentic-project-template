# Обновление проекта из шаблона

Инструкция Агенту. Выполняется из свежей копии шаблона `Runtime/update/<v>/`, которую загрузил
`Toolbox/tb update fetch` (skill `agentic-update`). `<v>` — имя этого каталога. Архитектура —
`setup/DESIGN.md` §6.4.

- Все команды — из корня проекта. Windows: `Toolbox\tb.cmd` вместо `Toolbox/tb`, пути через `\`.
- С человеком говори на языке проекта (`[project] language` в `.agents/agentic.lock`).
- Ничего не правь в `Runtime/update/<v>/`. Источник обновлений — только URL из `agentic.lock`; менять его
  (`tb update fetch --source`) может только человек.
- Ничего необратимого без явного «да» человека.

## 1. Предусловия

- `git status --porcelain` пуст. Если нет — покажи изменения. Незакоммиченные Знания предложи закоммитить
  (skill `kb-commit`), остальное — на решение человека. Пока дерево грязное, дальше не иди.
- Запомни текущую ветку (обычно `main`): в неё потом сливается обновление.
- Установленная версия — `[template] version` в `.agents/agentic.lock` (или `Toolbox/tb version`).

## 2. План

```sh
Toolbox/tb run Runtime/update/<v>/setup/update.py plan --project .
```

`--json` — для машинной обработки; план также сохраняется в `Runtime/update/plan.json`. Статусы:

| Статус | Значение |
|---|---|
| `unchanged` | Ничего не меняется |
| `update` | Шаблон изменил файл, локальных правок нет — будет заменён |
| `add` / `remove` | Новый / удалённый в шаблоне файл |
| `local-modified` | Локальная правка, шаблон файл не менял — останется локальная версия |
| `conflict` | Изменились и шаблон, и локальная версия — нужно решение |
| `seeded-changed` | Шаблон изменил исходную версию `seeded`-файла — только предложение, файл не трогается |
| `already-current` | Локальная версия уже совпадает с новой |

Плюс список миграций, которые будут выполнены.

## 3. Что меняется

Прочитай `Runtime/update/<v>/CHANGELOG.md`: все разделы новее установленной версии до `<v>` включительно.
Особое внимание — «Миграции» и ломающие изменения.

Для каждого `conflict` и `seeded-changed` посмотри разницу:

```sh
Toolbox/tb run Runtime/update/<v>/setup/update.py diff --project . <path>
```

## 4. Объяснение и решения

Расскажи человеку кратко:

- версии: с какой на какую; главное из CHANGELOG;
- сколько файлов по статусам; что удаляется (`remove`);
- каждый конфликт: в чём разница и твоя рекомендация:
  - взять шаблон — `--take-template <path>`;
  - оставить локальное — `--keep-local <path>`: изменения шаблона в этом файле в проект не попадут,
    а следующее его изменение в шаблоне снова даст конфликт;
  - взять шаблон и после применения вручную перенести нужные локальные правки; проектное лучше вынести
    из `managed`-файлов туда, где владеет проект (например, вне управляемого блока `AGENTS.md`);
- `seeded-changed`: что предлагает шаблон; согласованное внесёшь вручную после применения;
- миграции: что они изменят, особенно в `Knowledge/`;
- риски.

Согласуй решение по каждому конфликту. Конфликт без решения `apply` пропустит и оставит локальную версию —
лучше решить все. Жди явного подтверждения.

## 5. Применение

```sh
Toolbox/tb run Runtime/update/<v>/setup/update.py apply --project . --yes [--take-template <path>]… [--keep-local <path>]…
```

`apply` создаёт ветку `agentic/update-<v>`, применяет файлы и миграции, переписывает `agentic.lock`
и ничего не коммитит. `--no-branch` — только по просьбе человека. Прочитай вывод: пропущенные конфликты,
ошибки миграций. При ошибке остановись, покажи её человеку и предложи откат (§8).

## 6. Проверка

1. Внеси согласованные правки `seeded`-файлов и перенеси локальные правки (если так решили).
2. `Toolbox/tb kb lint` — исправь ошибки; нетривиальные исправления покажи человеку.
3. `Toolbox/tb agents link` — пересоздать адаптеры.
4. `Toolbox/tb agents doctor`.

## 7. Отчёт, коммит, слияние

1. Отчёт человеку: что обновлено, решения по конфликтам, миграции, что сделано вручную, что осталось;
   `git status --short`, `git diff --stat`.
2. После OK — коммит в ветке `agentic/update-<v>`. Только явные пути из `git status --porcelain`
   (удалённые — тоже через `git add -- <path>`), не `git add -A`:

   ```
   agentic: update to vX.Y.Z

   - <ключевые изменения>
   - Миграции: …
   - Конфликты: <path> — <решение>
   ```

3. После подтверждения слияния: `git switch <исходная ветка>`,
   `git merge --ff-only agentic/update-<v>`, `git branch -d agentic/update-<v>`.
4. Удали `Runtime/update/` целиком — последним шагом.
5. Предложи перезапустить агента, чтобы подхватились обновлённые skills и хуки.

## 8. Откат

Только с согласия человека. Ресурсы (`Resources/*`) и `Runtime/` обновление не трогает.

- **До коммита** (в ветке `agentic/update-<v>`; дерево перед `apply` было чистым):
  `git reset --hard`, `git clean -fd`, `git switch <исходная ветка>`, `git branch -D agentic/update-<v>`.
- **После коммита, до слияния:** `git switch <исходная ветка>`, `git branch -D agentic/update-<v>`.
- **После слияния:** `git revert <коммит обновления>` и коммит отката.

Затем `Toolbox/tb agents link` и `Toolbox/tb agents doctor`. `agentic.lock` откатывается вместе с файлами,
поэтому обновление можно повторить позже.
