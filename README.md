# Agentic Project

[English version](README.en.md)

**Agentic Project** — рабочая среда, в которой Агент комфортно работает над всеми Ресурсами проекта.
Этот репозиторий — шаблон `agentic-project-template`: из него проекты разворачиваются и через него
обновляются.

## Что такое Проект

**Проект** — это не один репозиторий, а связанное целое: инструкции и инструменты для работы, **Ресурсы**,
над которыми мы трудимся, и **Знания** о них. Корень проекта — собственный git-репозиторий.

- **Ресурсы** (`Resources/`) — то, что мы в итоге создаём: исходный код приложений и сервисов, техническая
  документация, скрипты, данные. Чаще всего это отдельные git-репозитории со своей историей и своими
  правилами. Их содержимое шаблон не регламентирует. Набор склонированных ресурсов у разных людей может
  отличаться — это нормально: полный список хранится в каталоге `Resources/resources.toml`.
- **Знания** (`Knowledge/`) — постоянная память проекта: всё, что нужно Агенту и Человеку для задач проекта
  и чего нельзя восстановить из Ресурсов и истории git. Знания быстро устаревают и обрастают шумом,
  поэтому регулярное ревью — обычная практика, а не исключение.
- **Агент** — ИИ-агент для работы с кодом и текстами: Claude Code, Codex и другие. Он читает `AGENTS.md`,
  ищет в Знаниях, пользуется инструментами проекта и работает с Ресурсами.

**Главное:** всё, что связано с проектом, живёт внутри проекта под git, а не в системных каталогах агентов
вроде `~/.claude`. Поэтому проект не зависит от конкретного Агента и переносится между машинами и людьми.

## Ключевые идеи

- **`.agents/` — единственный источник правды** для системного: skills, субагенты, хуки, MCP. Каталоги
  конкретных агентов (`.claude/`, `.codex/`, …) генерируются на каждой машине и в git не попадают.
- **Плавная деградация.** Достаточно агента, который читает `AGENTS.md` и выполняет команды. Нативные
  skills, субагенты и хуки — улучшение, а не требование.
- **В Знаниях — только невыводимое** из Ресурсов и истории git.
- **Механику делает скрипт, смысл — Агент.** Структура, ссылки, конфиги и миграции — в Toolbox. Интервью,
  анализ и тексты — в skills.
- **Дешёвый старт.** В начале сессии Агент читает только `AGENTS.md` и описания skills, Знания
  подтягиваются по требованию через поиск.
- **Никаких пустых каталогов.** В каждом лежит README с правилами — заодно это инструкция Агенту.
- **Необратимое подтверждает человек:** инициализацию, обновление, коммиты.

## Требования

- Агент: Claude Code, Codex или любой другой, который читает `AGENTS.md` и выполняет команды.
- git с настроенными `user.name` и `user.email`.
- Доступ в интернет при первом запуске.

Больше ничего не нужно. uv и Python скачиваются внутрь проекта, в `Runtime/`: глобально ничего не ставится,
права администратора не требуются. Поддерживаются macOS, Linux и Windows.

## Быстрый старт

```sh
git clone --branch v<версия> <url-шаблона> my-project   # последний релиз; без --branch — разработка
cd my-project
```

Дальше — один из двух путей.

**Через Агента (рекомендуется).** Откройте Агента в папке `my-project` и попросите инициализировать проект.
Он выполнит инструкцию `setup/INIT.md`: задаст вопросы (имя, язык, профиль, модули, агенты, ресурсы),
покажет сводку и после вашего подтверждения запустит init. Затем допишет проектную часть `AGENTS.md`,
заполнит каталог ресурсов и создаст первые Знания. Так же оборачиваются существующие репозитории — просто
скажите Агенту, что они уже есть.

**Вручную:**

```sh
./init.sh --name my-project --language ru --profile software --agents claude,codex --yes
```

На Windows — `init.cmd` с теми же флагами. Без `--yes` init ничего не меняет, `--dry-run` показывает план.
Необязательные модули включаются и выключаются флагами `--with` / `--without`, например
`--with devcontainer` или `--without obsidian`.

Init собирает проект из модулей, удаляет инсталлятор и **заменяет историю шаблона новым git-репозиторием**
с первым коммитом `agentic: init from template vX.Y.Z`, затем настраивает машину. URL шаблона сохраняется
в `.agents/agentic.lock` — по нему проект потом обновляется.

### Профили и модули

| Профиль | Для чего |
|---|---|
| `software` | Проекты с кодом: ресурсы — git-репозитории |
| `generic` | Проекты без кода (документация, исследования, данные): ресурсы — чаще обычные папки |

| Модуль | Состав |
|---|---|
| `core` | Всегда: `AGENTS.md`, `.agents/`, `Toolbox/`, правила `Runtime/`, настройки git |
| `knowledge` | Всегда: `Knowledge/`, `tb kb`, библиотекарь, skills работы со Знаниями |
| `resources` | Всегда: `Resources/`, каталог ресурсов, `tb resources` |
| `obsidian` | По умолчанию: настройка хранилища Obsidian на машине |
| `devcontainer` | По желанию: `.devcontainer/` для запуска Агента в контейнере-песочнице |

## Структура проекта

```
<project>/
├── AGENTS.md                 # точка входа для всех агентов
├── README.md                 # о проекте — для человека
├── .gitignore  .gitattributes  .ignore
├── .agents/                  # системное, источник правды
│   ├── agentic.lock          # происхождение из шаблона, профиль, модули, хэши управляемых файлов
│   ├── skills/               # процедуры (стандарт Agent Skills)
│   ├── agents/               # субагенты в каноническом формате
│   ├── hooks/                # hooks.toml с абстрактными событиями
│   ├── git-hooks/            # хуки git (pre-commit: kb lint, поиск секретов)
│   ├── adapters/<agent>/     # манифесты адаптеров
│   ├── mcp.toml              # каноническое описание MCP-серверов
│   └── docs/                 # концепция и справка — читаются по требованию
├── Knowledge/                # хранилище Obsidian
│   ├── README.md             # общие правила Знаний
│   ├── _templates/           # шаблоны заметок (tb kb new + Obsidian)
│   └── Decisions/ Entities/ Examples/ Gotchas/ Plans/ Tasks/   # в каждом — README.md с правилами
├── Resources/
│   ├── README.md             # правила работы с ресурсами
│   ├── resources.toml        # каталог ресурсов проекта
│   └── <name>/               # склонированные ресурсы (не в корневом git)
├── Toolbox/
│   ├── README.md             # индекс инструментов
│   ├── tb  tb.cmd            # единая точка входа
│   ├── agentic/              # инструменты шаблона (управляемые)
│   └── …                     # инструменты проекта
├── Runtime/                  # не в git
└── .claude/  .codex/  CLAUDE.md  …   # генерируемые адаптеры, не в git
```

**Toolbox** — коробка с инструментами проекта и заодно слой независимости от хостовой системы.
`Toolbox/tb` (на Windows `Toolbox\tb.cmd`) — единая точка входа: сам находит или скачивает uv и Python.
`Toolbox/agentic/` — инструменты шаблона. Всё остальное — инструменты проекта: скрипты, которые
автоматизируют рутину или редкие, но трудоёмкие действия. Они запускаются через `tb run <script>`
и описываются в `Toolbox/README.md`.

**Runtime** — место для временного и некритичного: логи, скетчи, одноразовые скрипты, промежуточные данные.
Всё, что появилось в процессе работы, лежит в одном месте и удаляется осознанно. Здесь же живёт среда
(`tools/`, `cache/`) и копия шаблона при обновлении (`update/`) — эти подкаталоги зарезервированы,
остальная структура на усмотрение исполнителя. `Runtime/` не попадает в git; после его удаления следующий
вызов `tb` восстанавливает среду.

## Знания

| Тип | Что хранит | Срок жизни |
|---|---|---|
| Decisions | Архитектурные решения (ADR): контекст, решение, отвергнутые альтернативы, последствия | Пока решение действует |
| Entities | Карточки сущностей: назначение, где лежит в Ресурсах, связи, неочевидные инварианты, владельцы. Не пересказ кода | Пока сущность жива |
| Examples | Переиспользуемые примеры и шаблоны, которые можно быстро найти и применить | Пока актуальны |
| Gotchas | Грабли: симптом, причина, обход, как проверить актуальность (`applies_to: [node@22]`) | Пока жива причина |
| Plans | Идеи, отложенное и обнаруженное по ходу работы | До превращения в задачу или отказа |
| Tasks | Спецификация текущей задачи: цель, детали, решения по ходу, прогресс, итоги | До сбора итогов |

В Знаниях только живое: устаревшее исправляют на месте, отжившее (заменённое решение, устранённые грабли,
отвергнутый план) удаляют — прежние версии хранит история git.

Решения, принятые внутри задачи, живут в задаче и уходят вместе с ней. В Decisions попадают только те,
что переживают задачу.

```
Plans (idea) ──► Tasks (active) ──► done ──► сбор итогов ──► удаление задачи
                                                 │
                             Decisions / Gotchas / Entities / Examples
```

Заметки — Markdown с YAML-frontmatter и относительными ссылками: их одинаково понимают агенты, IDE, GitHub
и Obsidian. Инструменты: `tb kb search` (BM25 со стеммингом для русского и английского), `tb kb new`,
`tb kb lint`, `tb kb stale`. Процедуры — skills `kb-lookup` (библиотекарь: найти и проверить ответ),
`wrap-up` (итоги сессии), `kb-commit` (коммит Знаний), `kb-review` (ревью Знаний).

## Жизненный цикл

**Инициализация** — см. [Быстрый старт](#быстрый-старт). При обёртывании существующих проектов (adopt)
репозитории клонируются в `Resources/` заново, а не перемещаются: перемещение ломает всё, что привязано
к абсолютному пути (история и память агентов, настройки IDE). Личные знания — встроенная память агентов,
заметки — Агент раскладывает по типам Знаний, человек подтверждает.

**Новая машина:**

```sh
git clone <репозиторий-проекта>
cd <проект>
Toolbox/tb setup --agents claude,codex   # Windows: Toolbox\tb.cmd setup --agents claude,codex
```

`tb setup` скачивает uv и Python в `Runtime/`, создаёт адаптеры перечисленных агентов (список запоминается
в `.agents/local.toml` этой машины), применяет настройки git и Obsidian и показывает, каких ресурсов
из каталога не хватает (`--clone-missing` склонирует их). Та же команда восстанавливает среду после удаления
`Runtime/` и подключает нового агента (`--agents`).

**Работа.** На старте сессии Агент читает `AGENTS.md`, перед решениями ищет в Знаниях (`kb-lookup`),
в конце подводит итоги (`wrap-up`), периодически проводит ревью (`kb-review`). Коммитит только по вашей
просьбе.

**Обновление.** Попросите Агента обновить проект — сработает skill `agentic-update`. `tb update fetch`
загружает последний релиз шаблона в `Runtime/update/<версия>/`, и Агент выполняет `setup/UPDATE.md`
из этой свежей копии — так обновляется и сам механизм обновления. Агент показывает план, изменения
по `CHANGELOG.md`, конфликты и миграции, после вашего подтверждения применяет их в ветке
`agentic/update-<версия>`, проверяет проект и коммитит. Слияние — после вашего OK, откат — средствами git.

Тем же механизмом меняется состав проекта: добавить или убрать модуль, сменить язык или профиль
(`--add-module`, `--remove-module`, `--language`, `--profile`; без нового релиза — из копии установленной
версии, `tb update fetch --ref v<версия>`).

### Владение файлами

| Класс | Владелец | Что делает обновление |
|---|---|---|
| `managed` | шаблон | Заменяет, если файл не менялся локально; иначе — конфликт, решает человек |
| `seeded` | проект (создан из шаблона один раз) | Не трогает, может предложить изменения |
| `block` | смешанный | Обновляет только блок между маркерами `agentic:begin` и `agentic:end` (`AGENTS.md`, `.gitignore`, `.gitattributes`, `.ignore`) |
| остальное | проект | Не трогает |

Классы и хэши записаны в `.agents/agentic.lock` — это база для трёхстороннего сравнения при обновлении.
Шаблоны заметок `Knowledge/_templates/` — `seeded`: их можно править под проект.

## Агенты

Система рассчитана на агентов с разными возможностями:

| Уровень | Агент умеет | Как работает система |
|---|---|---|
| 0 | Читать `AGENTS.md` и выполнять команды | Протокол записан текстом в `AGENTS.md`, процедуры — в `.agents/skills/`, инструменты — `tb` |
| 1 | Нативные skills | Skills подхватываются автоматически |
| 2 | Субагенты | Библиотекарь и другие работают в изолированном контексте |
| 3 | Хуки | Автоподсказки из Знаний по тексту запроса |

Уровень 0 обязан работать полностью — это гарантия для новых и более слабых агентов.

Стартовые адаптеры — **Claude Code** и **Codex**, оба поддерживают все уровни. `tb agents link` подключает
к ним skills и генерирует из `.agents/` субагентов, хуки и MCP, а также отключает встроенную память агента:
память проекта — только `Knowledge/`. `tb agents doctor` проверяет, что всё на месте и актуально.

Новый агент — это новый каталог `.agents/adapters/<agent>/` и, при необходимости, генератор
в `Toolbox/agentic/adapters/`. Ядро не меняется, новые адаптеры приходят в проекты обычным обновлением.
Опенсорсной или китайской модели внутри уже поддержанного агента адаптер не нужен.

## Языки

Шаблон поставляется на русском (по умолчанию) и английском. Язык выбирается при init, и проект получает
только его: дубли переводов остаются в шаблоне и не раздувают контекст Агента. Сообщения `tb` всегда
на английском. Сменить язык позже можно обновлением с `--language` — переводятся файлы шаблона,
а не свои файлы проекта.

## Версии

Релиз шаблона — git-тег `vX.Y.Z` (semver) с разделом в [CHANGELOG.md](CHANGELOG.md), где обязательно
описаны миграции. Обновление берёт последний релиз, а не текущее состояние ветки. Проект, развёрнутый
из форка, обновляется из этого форка.

Между релизами `setup/VERSION` содержит следующую версию с суффиксом `-dev` (например, `0.2.0-dev`).
Проект, развёрнутый из такого состояния, init предупреждает об этом, а обновление предложит релиз `0.2.0`,
как только он выйдет. Для реальных проектов берите тег релиза.
